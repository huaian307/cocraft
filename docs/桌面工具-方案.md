# Agent 通用桌面工具（Computer Use）方案 v1.0

> 状态：**P0 只读 + P1 动作 + ACP 接入已实现**（2026-10-26，`ui 0.2.73` 开发版；回归 `tools/cu_test.py` **44 项全绿**）
> 目标：给所有接入 cocraft 的 agent（Codex / Claude / OpenCode / dsh…）一套**统一的“看窗口、找控件、点击、输入”工具**，替代每个模型自己写截图 + 鼠标脚本。
> 一句话：**模型是大脑；这套工具是眼睛和手；cocraft 是身体 + 护栏。**

## 0. 实现记录（相对本方案原文的改动）

| 项 | 方案原文 | 实际实现 | 为什么改 |
| --- | --- | --- | --- |
| **交付通道** | MCP 优先 + CLI | **CLI 是基线**（放 PATH），**每轮 prompt 注入工具卡**，MCP 暂缓 | ACP 协议**没有“客户端自定义工具”**：agent 的工具是它自己的。要做到“像 skill 一样人人可用”，只能**命令在 PATH + prompt 里讲一句**（跟 `inject_skill` 同一思路） |
| **权限弹窗** | 逐个确认 | `cu` 命令在 ACP 权限层**自动放行**（只读永远、动作放行但真闸门在 cu 进程里）；带 `--allow-actions` 的**不**自动放行 | 不这么做，一个 GUI 任务会弹几十次审批（实测 Codex 发邮件 50 次），工作流根本跑不动 |
| **UIA 宿主** | 每次调一个 PowerShell（0.3~1s） | **常驻宿主** `tools/uia_host.ps1` + JSON 行（空闲 90s 自杀） | `tree → find → click` 三次冷启动就 3 秒起步；常驻后每次 20~150ms |
| **截图** | 调 `win_shot.ps1` | **纯 ctypes GDI + zlib 手写 PNG**（`PrintWindow`） | 不启进程、不依赖 PIL、一次 ~30ms |
| **动作兜底** | UIA 优先 | UIA 模式**不可用时**用**UIA 报的矩形**做坐标点击（不是像素猜） | 实测 WinForms/MSAA 控件 `ControlType=Pane`、**没有任何 Pattern**；矩形来自 UIA，仍然不是“截图猜坐标” |
| **额外工具** | — | `cu_act` 的思想落成 `click/type --name`（**一次调用 = find + 动作**） | 少两次往返，直接把 50 步压到 ≤8 步 |

**踩坑（都已修，写进 AGENTS.md 踩坑 #54）**

1. `ConvertTo-Json -Depth 12` 超深时把对象**变成字符串**（表现为 Python 端 `'str' has no attribute 'get'`）→ 改 `-Depth 100`。
2. 请求信封的 `id` 和元素 `id` **撞车**：`[int]"e1"` 抛错 → 宿主回 `id:0` → Python 判定 id 不匹配 → **干等 60 秒超时**。元素改用 `element` 字段；并且把"不匹配的响应"记下来，超时信息里带上它。
3. `.ps1` **必须纯 ASCII**：加了两行中文注释 → PowerShell 5.1 按 ANSI 读 → 解析器报 `UnexpectedToken`，宿主直接退出（和踩坑 #9/#28 同源）。
4. `SetForegroundWindow` 被前台锁拒绝 → **首次点击被"激活窗口"吃掉**（表现为 7+8 算出 8）。绕法：轻敲一下 Alt 再抢前台。
5. `int(c_void_p)` 抛 `ValueError: invalid literal for int() ...`（拿的是句柄内存字节）→ `_hwnd_int()` 走 `.value`。
6. 64 位句柄没声明 `restype` → `GlobalAlloc`/`GetClipboardData` 被截成 32 位 → 剪贴板**永远失败**。
7. `LegacyIAccessiblePattern` 在本机 .NET 上**类型都不存在** → 懒解析 + try/catch，不可用就退回坐标点击。

# 以下是 v0.1 方案原文（保留作背景）

---

## 1. 为什么要做

这次 Codex 发邮件的实测：

- 50 次权限审批、约 100 条活动；
- 每一步都是“截图 → PIL 扫像素/颜色 → 猜坐标 → `mouse_event`”；
- 反复 `AppActivate` / `SetForegroundWindow` 抢焦点；
- 换一个模型 / 换一个窗口，整套脚本都要重写。

问题不在模型不够聪明，而在**每个 agent 都在重新发明鼠标**。

如果 cocraft 提供一层标准工具：

- 模型只需要说“点『写信』按钮”，工具负责找到并点击；
- 不用截图猜坐标；
- 所有动作统一走权限、审计、焦点和桌面租约；
- 所有 agent 共享同一套能力。

---

## 2. 定位：不是新模型，也不是新 agent

| 层 | 角色 |
| --- | --- |
| 大模型 | 推理、决定下一步 |
| Agent（Codex / Claude / OpenCode） | 模型 + 循环 + 工具 + 记忆 |
| **cocraft 这套工具** | **agent 的眼睛、手、桌面租约、权限与审计** |

它让 cocraft 从“聊天前端”变成“agent 运行时 / 身体”，但不会替代模型。

---

## 3. V1 范围

### 3.1 做

| 工具 | 作用 | 权限 |
| --- | --- | --- |
| `cu_windows` | 列窗口：标题 / PID / HWND / 类名 / 矩形 / 是否可见 / 是否前台 | 只读 |
| `cu_uia_tree` | 导出目标窗口的 **UI Automation 树**（名称 / 角色 / AutomationId / 范围 / 可用模式） | 只读 |
| `cu_uia_find` | 按名称 / 角色 / AutomationId 查找控件 | 只读 |
| `cu_shot` | **只截目标窗口**（PrintWindow），DPI 感知，不要求前台 | 只读 |
| `cu_clipboard_get` | 读剪贴板 | 只读 |
| `cu_wait` | 等窗口 / 控件 / 文本出现（带超时） | 只读 |
| `cu_click` | 点击 UIA 控件（优先）或坐标（兜底） | 动作 |
| `cu_type` | 向控件 / 窗口输入文本（优先 UIA，兜底 SendInput / 剪贴板） | 动作 |
| `cu_keys` | 发送快捷键（Ctrl+S 等） | 动作 |
| `cu_clipboard_set` | 写剪贴板 | 动作 |

### 3.2 不做（V1 明确不做）

- OCR / 视觉模型依赖（UIA 能覆盖大部分 Windows 应用）；
- 全屏截图 + 像素猜坐标（`cu_shot` 只截窗口）；
- 浏览器 DOM / CDP（V1.5 单独做 `browser_*`，比桌面截图可靠）；
- UAC / 安全桌面 / 提权窗口自动化（直接拒绝并说明原因）；
- 独占全屏 / DRM / 游戏；
- 多 agent 同时控制鼠标键盘（V1 用桌面租约串行化）。

## 4. 架构

```text
Codex / Claude / OpenCode / dsh
        │
        ├─ MCP stdio:  tools/cu_mcp.py
        └─ CLI:        tools/cu.py
                              │
                              ▼
                 backend/computer/
                 ├─ winapi.py      枚举窗口 / 前台 / DPI
                 ├─ uia.py         调 tools/uia_dump.ps1（.NET UIAutomation）
                 ├─ capture.py     调 tools/win_shot.ps1（PrintWindow）
                 ├─ input.py       纯 ctypes：SendInput / 鼠标 / 剪贴板
                 ├─ lease.py       桌面租约（同一时刻一个控制者）
                 ├─ gate.py        权限判定（只读 / 动作 / 拒绝）
                 └─ audit.py       写 backend/audit.py（kind=cu）
                              │
                              ▼
        Windows API / .NET UIAutomation / PrintWindow
```

### 为什么 UIA 先用 PowerShell

- 系统 Python 没有 `comtypes` / `pywinauto`；
- `.NET UIAutomation` 是 Windows 自带的，PowerShell 直接 `Add-Type` 就能用；
- 沿用现有 `tools/pick_folder.ps1` / `pick_image.ps1` 的模式（纯 ASCII、无新依赖）；
- 单次调用约 0.3~1s，V1 可接受；后续可换常驻 UIA 助手或 `comtypes`。

## 6. 权限与安全（必须一起做）

### 6.1 权限

| 调用 | 默认 |
| --- | --- |
| 只读工具（`cu_windows` / `cu_uia_tree` / `cu_uia_find` / `cu_shot` / `cu_clipboard_get` / `cu_wait`） | `read` 及以上自动放行，但**全部入审计** |
| 动作工具（`cu_click` / `cu_type` / `cu_keys` / `cu_clipboard_set`） | 需要 `exec` / `trust`，或显式 `--allow-actions` |
| 危险动作（文本里含“发送 / 删除 / 支付 / 提交 / 卸载…”） | **永远人工确认**，V1 直接拒绝并让 agent 换方式 |
| UAC / 安全桌面 / 提权窗口 | **拒绝**，返回人话原因 |
| 应用黑名单 | 密码管理器 / 银行 / 安全软件默认拒绝（`_cu.json` 可配） |

### 6.2 工作流里的权限来源

`orchestrator._run_member` 给成员注入环境变量：

```text
COCRAFT_CU_ACTIONS = allow | deny        # trust = allow，其他 = deny
COCRAFT_CU_ACTOR  = <engine>/<member>
COCRAFT_CU_RUN    = <run_id>
```

- `trust` 成员：动作工具自动放行（非危险、非黑名单应用）；
- `exec` / `ask` 成员：动作工具 **deny**，返回“请在检查器把权限改成信任，或手动操作”；
- 单聊 agent：默认 deny；设置里可开“允许桌面操作”。

> V1 先用环境变量做 fail-closed；V1.5 再接托盘热键/审批抽屉逐条确认。

### 6.3 桌面租约

```text
runtime/state/_cu_lease.json
{ "owner": "run_xxx/m1", "token": "...", "expires": 1792980000 }
```

- 只有持有租约的 agent 能点击/输入；
- 每次动作续租 30 秒；
- 其他 agent 返回 `{ok:false, busy:true, owner:...}`，排队或放弃；
- 只读工具不需要租约。

### 6.4 审计

写入现有 `backend/audit.py`（`kind=cu`）：

- 工具名、窗口标题/类名、控件名/角色/AutomationId、坐标；
- 输入文本只记**长度 + 哈希 + 前 40 字**（可配脱敏）；
- 截图**只记路径**，不把图片内容写进链；
- 结果 ok / error / denied。

### 6.5 截图与隐私

- `runtime/cache/cu/`，默认保留 **10 分钟 / 最多 30 张**；
- 设置里可关闭截图；
- 密码框（UIA `IsPassword=true`）禁止截图/读取文本；
- 审计不记录文本正文。

### 6.6 焦点

- `cu_shot` 用 `PrintWindow`，**不抢前台**；
- `cu_click` / `cu_type` 才激活窗口；`restore_focus=true` 时动作后把前台还给上一个窗口；
- 工作流进入 GUI 任务时：面板自动收起到托盘，审批走热键；
- 永远不用“全屏截图 + 猜坐标”作为默认路径。

## 7. 接入方式

### 7.1 CLI（所有 agent 都能用）

```bat
python tools\cu.py windows --title QQ
python tools\cu.py uia-tree --hwnd 123456 --depth 4
python tools\cu.py find --hwnd 123456 --name 写信 --role Button
python tools\cu.py click --hwnd 123456 --element e2
python tools\cu.py type --hwnd 123456 --element e5 --text "你好"
python tools\cu.py shot --hwnd 123456 --out runtime\cache\cu\mail.png
```

输出统一 JSON；失败退出码 1 + `{"ok":false,"error":"..."}`。

### 7.2 MCP（结构化工具，推荐给支持 MCP 的 agent）

`tools/cu_mcp.py`（stdio JSON-RPC）：

- `initialize`
- `tools/list`
- `tools/call`

Codex / Claude / OpenCode 各自配置里加一条本地 MCP server 即可；不自动改用户配置，V1 只给示例和文档。

### 7.3 共享规则

在两份 `AGENTS.md` 里加：

> 需要操作桌面时，**先用 `cu_uia_tree`/`cu_uia_find`**，不要截图猜坐标；  
> 发邮件 / 调 API 优先用对应工具，GUI 是最后手段。

## 11. 风险与边界

| 风险 | 说明 / 对策 |
| --- | --- |
| UIA 覆盖不全 | 部分自绘 / 游戏 / 远程桌面只能截图；V1 返回“UIA 不可用”，不硬猜 |
| 提权窗口 | 非提权进程无法 SendInput；检测到提权直接拒绝 |
| UAC / 安全桌面 | 无法自动化；只能人工 |
| 浏览器 | Chromium 的 UIA 很浅；V1.5 用 CDP / DOM，不用桌面像素 |
| 截图隐私 | 临时缓存 + 密码框禁止 + 审计不记正文 |
| 多 agent 抢鼠标 | 桌面租约串行化 |
| 模型不会用 | AGENTS 规则 + MCP 工具描述 + 示例 |
| MCP 配置 | 每个 agent 配置不同；V1 给示例，不自动改用户配置 |

## 12. 需要拍板

1. **UIA 实现**：V1 用 PowerShell + .NET（无依赖）还是直接装 `comtypes`/`pywinauto`？
   - 建议：**先用 PowerShell**，跑通后再考虑常驻助手。
2. **动作默认权限**：默认 deny / 仅 `trust` 允许 / 默认确认？
   - 建议：**默认 deny；工作流 `trust` 成员 allow；单聊需设置里显式开**。
3. **MCP 与 CLI 的顺序**：建议同一版都做，CLI 先跑通。
4. **截图保留**：10 分钟 / 30 张是否合适？
5. **应用黑名单**：V1 先内置密码管理器/银行/安全软件，是否够？

## 13. 结论

这套工具做出来之后：

- 所有接入 cocraft 的模型/agent 共享同一套“眼睛和手”；
- 不再每个模型自己写截图 + 鼠标脚本；
- 动作统一走权限、审计、焦点和桌面租约；
- cocraft 从“聊天前端”变成 **agent 的身体 + 护栏层**。

它不是“另一个大模型”，但确实让 cocraft **接近于一个 agent 平台**。
