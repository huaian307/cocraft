## 4. 决策与结论（写下来省下次重复讨论）

### 4.1 「GitHub 技能」要不要投

调研（现查）：`SKILL.md` 是事实标准（Claude/Codex/Cursor/Copilot/Gemini/OpenCode/Windsurf 都读），
有实测显示 **10 个技能里约 8~9 个天生通用**，不通用的是用了 `allowed-tools` / `context: fork` / 子 agent / MCP 的。

**结论（`docs/技能-生态与兼容-方案.md`）**：**不建生态**（格式是公共品），只做
**P0（目录补齐 + 兼容性体检 + 小标）** 和 **A/B/C 反馈通道**（诊断包 / 出口 / 静默失败提示）；
**P1 工具映射冻结**（有真实报错再做）；**明确不做**静默埋点。

### 4.2 「GPT 都没用完，为什么还要撤销」——回收站兜不住

本机实测（`%TEMP%` 造文件 + 查回收站条数）：

| 删除方式 | 回收站里有没有 |
| --- | --- |
| `cmd del /f /q` | **没有** |
| `Remove-Item -Force` | **没有** |
| `rmdir /s /q` | **没有** |
| `[IO.File]::Delete()` | **没有** |
| `python os.remove` | **没有** |
| 对照：Shell API（资源管理器那套） | **有** |

⇒ agent 的世界是"直接 unlink"，**回收站接不住**；而且回收站只管"删"、不管"改"（覆盖写才是 agent 的主业）。
所以「先隔离 + 每轮快照 + 审计」不是重复建设，是补回收站补不上的三块。

### 4.3 产品定位（延续 `docs/竞品与定位.md`）

**不卖"恢复软件"，卖"敢让它动你电脑"**：事前留底 + 每步入链 + 能不能退。
界面上每一处"说不清"（报错、工作区、预览）都是在削弱这个卖点，所以这几版优先修这些。

## 9. `0.2.95` 低风险删除（2026-11-02 追加）

**要解决**：agent 一次重构会发几十条 `rm` / `Remove-Item`，逐条弹窗把「可逆执行」变成「可烦执行」。

**做法**：只给「**明确可再生成**」的删除开一条窄路，而且必须是「**先隔离、再放行**」。

| 环节 | 落点 |
| --- | --- |
| 评级 | `backend/file_rank.py`：★1 = 构建产物 / 缓存 / 日志 / 临时；★5 = 源码 / 配置 / 密钥 / `.git` / `runtime/state` / 区外 / 根目录 |
| 只认删除 | `rm` / `del` / `rmdir` / `Remove-Item` / `os.remove` / `shutil.rmtree`；`shutdown` / `taskkill` / `format` / `reg delete` / 移动 / 复制 / 写文件 **一律照旧问** |
| 命令解析 | PowerShell / CMD / Python / Node / .NET 的常见删除写法都解析目标；变量 / 拼接 / 解析不出 → `unresolved`（fail-closed，退回弹窗） |
| fail-closed | 目标解析不全、在区外、git 跟踪、隔离被跳过任何一项 → 退回弹窗 |
| 接线 | ACP：`service.py::_ask_permission`；OpenCode：前端轮询到申请 → `POST /permission/ticket` → `OpenCodeEngine.auto_ticket` |
| 留痕 | 每条 auto 记录带 `scores` / `expires_at` / `tombstone`；自动放行写审计 `decision=allow`（`actor=file_rank`） |
| 保留期 | 默认 7 天；第 6 天托盘 + 横幅提醒；到期**只清安全项**（原件已恢复 / 本来就是 ★ / 墓碑） |
| 风险项 | git 跟踪文件已缺失 / 无法判定 → **hold 永久保留**，每天最多提醒一次 |
| 墓碑 | 一次隔离内容 > 64MB 就只记清单（`node_modules` 不该占磁盘），面板标「仅清单」、恢复时明确说无法恢复 |
| 开关 | 设置「低风险删除」（默认开）；隔离区页有策略条（阈值 / 保留天数 / 立即清理） |

**回归**：`file_rank_test` 61 · `command_parse_test` 40 · `quarantine_cleanup_test` 44 · `low_risk_delete_test` 16；
`check_features` 2309 → **2344**，`run_suite` 54 → **59**。

**明确的边界**：这不是"放开破坏性操作"。判断标准是**"出事能不能完整恢复"**，不是"看起来像不像垃圾"。

## 10. 构建可复现（2026-11-03 追加）

**问题**：安装包解决的是**最终用户运行时**（嵌入式 Python / node / agent / 组件全自带），但**构建**这一步不可复现：

- `build.py` 写死 `D:\agentlist\...` 的 node / codex 路径；
- `claude-code-acp` / `opencode-ai` 用 npm 装**不带版本**；
- 组件 venv 是手工 `pip install`，版本未锁；
- CI 不校验构建依赖。

**做了**：

| 项 | 落点 |
| --- | --- |
| 依赖锁 | `packaging/deps.lock.json`：Python 3.12.10（URL + SHA256）、Node 22.23.3（`node.exe` SHA256）、4 个 npm 适配器、Codex 依赖树、3 个组件 venv 的 `pip freeze` |
| 路径参数化 | `COCRAFT_NODE_SRC` / `COCRAFT_CODEX_NM` 环境变量 + 常规位置 + 仓库内 `agents/` 兜底；找不到时**明确报错**，不再静默出残包 |
| 版本校验 | Python / node 的 SHA256；npm 按锁补 `@版本`；codex / 组件版本漂移**默认失败**（`--allow-drift` 可临时跳过） |
| 自检 | `python packaging/build.py --check-lock [--strict]`（CI 跑这条） |
| 文档 | `docs/BUILD.md`：前置、素材、构建、更新依赖、可复现边界、排错 |
| 开发环境 | `scripts/bootstrap-dev.ps1`（纯 ASCII）：按锁重建 3 个 venv |
| 回归 | `tools/build_lock_test.py` **34 项**（schema / 补版本 / SHA256 / 组件与 codex 版本 / 漂移拦截 / `--check-lock`） |

**还没锁**：Inno Setup 的具体小版本、npm 的**传递依赖**（顶层包已锁）、`dist/cache` 的下载源。
要做到**字节级可复现**，下一步是把 `package-lock.json` 纳入 `packaging/` + CI 完整构建并记录产物 SHA256。

> 一句话：**用户不用装依赖，但构建者要能"换台机器打出同一个包"；现在版本可复现，字节级还没到。**

## 11. `0.2.96` Agent / Node 更新补全（2026-11-04 追加）

**问题**：更新链路只覆盖了一半，而且安装版上有一个**真 bug**：

- 面板内 npm 安装的 agent 能查版本、能一键更新，但**没有回滚**；
- 自带 agent（`agents/codex` / `claude` / `opencode`）**没有独立更新入口**，只能随安装包；
- 没有后台检查（只有打开弹窗才查），也没有可选自动更新；
- Node 运行时固定，不能更新；
- **`build.py::_stage_node` 只拷 `node.exe`，没拷 `node_modules/npm`** → 安装版 `agent_install.node_and_npm()` 找不到 npm，面板内更新按钮**完全不可用**。

**做了**：

| 问题 | 落点 |
| --- | --- |
| 打包不带 npm | `_stage_node` 整包 `node_modules/npm`（10.9.9）+ `deps.lock.json` 锁 `npm_version`；`node_and_npm()` 在随包 node 缺 npm 时**回退系统 node** |
| 更新失败不能退 | `_backup_dest` / `_restore_backup`：更新前把整个安装目录 **rename** 成 `.bak-<ts>`，失败自动放回；成功后保留最近 1 份 |
| 手动回滚 | `agent_install.rollback()` + `POST /agent/rollback`；UI 每个已装项带「回滚」按钮（显示备份版本） |
| 后台检查 | `agent_updates_keeper()` 每 6h；`GET /agent/updates`（`?cached=1` 只读缓存，启动横幅用）；有新版写托盘气泡 + 横幅 |
| 可选自动更新 | `runtime/state/_agent_auto.json`：`check` 默认开、`autoInstall` 默认关、`channel=patch`；`auto_tick()` 只在 **ACP 无活跃轮次** 时一次装一个 |

## 12. `0.2.99`~`0.2.102` 忏悔室：三类 → 项目 → 文件版本时间线（2026-11-04 追加）

**用户需求**：不要只按“隔离区记录”平铺；先按 **群聊 / 工作流 / 单聊** 三类，再按项目，做成时间线，允许**指定文件回滚到指定版本**。随后明确：**恢复中心和隔离库合并成「忏悔室」**，删除的文件、被修改的旧版都要自动存放。

**实现**：

| 项 | 落点 |
| --- | --- |
| 后端聚合 | `backend/restore_center.py`：把忏悔室（删除前副本 / 修改前旧版）与轮快照（`with_content` 才有内容）统一成 `(分类, 项目, 文件)` 索引 |
| 自动留存 | `backend/engines/base.py` 的 `capture_before_allow()`：单聊 ACP / OpenCode 反代 / 工作流 / 群聊四条审批路径在**放行前**把目标旧版复制进 `runtime/quarantine/`，记录 `kind=delete|modify` |
| 分类规则 | `chat-*` / `agent-*` / `cc-*` → 群聊；`run_*` / `wf-*` → 工作流；其余（`panel-*` / `ses_*` / uuid）→ 单聊 |
| 项目 | 取记录里的 `root`；没有工作目录归「（无项目）」 |
| 时间线 | 同一文件的版本按时间新→旧；相同 hash 的连续版本去重；标「删除前 / 修改前 / 快照」 |
| 单文件回滚 | `POST /restore/file`：快照版本从内容仓取 blob；忏悔室版本从 `files/` 取副本。**回滚前先把当前文件复制进忏悔室**，回滚也可逆 |
| 安全 | 墓碑（只记清单）/ 无内容快照 / 内容已回收 → 明确拒绝；快照目标必须落在原 `root` 内 |
| 接口 | `GET /restore/overview`、`GET /restore/timeline`、`POST /restore/file` |
| 界面 | 扳手 →「忏悔室（按文件版本）…」：左栏三类 + 项目，右栏文件版本；底部「全部记录与策略…」保留原隔离库的保留期 / 低风险开关；「按 git 提交清理…」可手动触发 |
| 回归 | `tools/restore_center_test.py` 36 项（分类 / 项目 / 时间线 / 去重 / 修改前留存 / 两条回滚 / 自动备份 / 墓碑 / 无内容 / 非法分类） |

**按 git 提交出清（`0.2.101`）**：

- `backend/confessional_git.py`：后台每 60s 看一次项目 HEAD；**首次只记基线**，之后 HEAD 变化才清。
- 只清 `taken_at <= HEAD 提交时间` 的记录；提交之后的新改动留到下一次 commit。
- 逐项把忏悔室副本算成 **git blob SHA1**，用 `git cat-file` 确认对象存在；不是只看“路径有没有历史”。
- 未跟踪 / 未提交的旧内容 → **保留**（fail-closed），面板按钮会显示保留条数。
- 旧快照同样处理：只有「当前已变 / 已删」的旧文件内容都能在 git 找到才删；未改过的大文件不参与判断。
- 手动入口 `POST /confessional/git-clean`；自动入口 `confessional_git_keeper`。
- 回归 `tools/confessional_git_test.py` 10 项（已提交清 / 未跟踪留 / 删除清 / 快照清 / 首次基线）。

**删除「撤销这一轮」（`0.2.102`）**：

- 工具菜单、弹窗、快捷键、`UNDO` 状态、工具栏高亮、测试全部移除。
- 每轮快照保留，但只作为**忏悔室的版本来源**；不再提供“整轮一键退回”。
- 群聊 / 工作流审计页里的「轮快照退回」仍保留：那是按 scope 的单次快照恢复，不是原来的“撤销这一轮”。

**边界**：

- 审批路径会自动留存；如果 agent 的运行模式**完全绕过审批**（如 danger-full-access），仍建议打开「每轮工作区快照」并勾选**轮快照带内容**兜底。
- 轮快照默认**只记文件名**；要能回滚内容，必须在设置里打开「每轮工作区快照」并勾选**轮快照带内容**（否则时间线里显示「仅记录」）。
- 群聊 / 工作流的快照默认是否带内容，分别由 `groupContent` 与工作流配置决定；没带内容的历史版本无法回滚。
- 忏悔室超过 64MB 的可再生文件只留墓碑，时间线里能看到「删除前（仅清单）」，但不能回滚。
- 单聊的会话标题只在本地 `_acp_sessions.json` 里有；OpenCode 上游会话（`ses_*`）目前回退显示 id 前缀。
- `restore-*` 作用域是回滚时的自动备份，会出现在时间线里，属于正常记录。
