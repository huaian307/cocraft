# 前端优化方案（无构建 · 原生 JS）

> 状态：**✅ 已完成（2026-10-22，`ui 0.2.20` 交付）** —— P0~P5 全部落地，见文末「实施结果」
> 约束：**不引入构建步骤 / 框架 / TypeScript**；WebView2 + Edge 直接跑原生 JS
> 相关：`frontend/app.js`（已拆成 `js/` + boot）、`frontend/style.css`（已拆成 `style/`）、`frontend/index.html`、`tools/` 无头回归

---

## 0. 现状数据（实测，2026-10-22）

| 项 | 数值 |
| --- | --- |
| `app.js` | **15,140 行 / 671.7 KB**（单文件） |
| `style.css` | **4,070 行 / 206.3 KB / 约 1,506 条规则** |
| `index.html` | 1,221 行 / 69.4 KB |
| 函数 | **751 个** `function` + 876 个箭头函数 |
| 事件 | **369 个 `addEventListener`**（window 36 / document 21） |
| 定时器 | **14 个 `setInterval`**（70 / 500 / 1000 / 1500 / 2000 / 4000 / 20000 / 25000 ms） |
| DOM 写入 | **204 处 `innerHTML`**、867 处 `$()`、38 处 `querySelectorAll` |
| 存储 | 85 处 `localStorage` 直接读写 |
| CSS | 1,497 处 `var(--…)`（好）、18 处 `!important` |

**结论**：功能没问题，但已经进入「单文件 + 全量重绘 + 多路轮询」的维护与性能危险区：
- 启动时一次性解析 672 KB 脚本，任何功能改动都要动同一个文件；
- 长会话 / 工作台大量 `innerHTML` 重建，滚动与输入可能被拖慢；
- 14 个定时器没有统一的「页面隐藏就停」策略；
- 弹窗 / 抽屉 / Esc / 滚动锁各写各的，状态容易打架。

## 1. 目标与非目标

### 目标
1. **可维护**：拆成 10~14 个无构建脚本，单文件 ≤ 100 KB，改动范围可预测。
2. **更快**：首屏解析与长会话渲染明显下降；空闲 CPU/内存更稳。
3. **更一致**：弹窗/抽屉/焦点/Esc 统一管理；错误可见（接诊断包）。
4. **零构建**：仍然 `<script defer>` 顺序加载，WebView2/Edge 直接跑。

### 非目标（本轮不做）
- ❌ 引入 React/Vue/Svelte、Vite/Webpack/esbuild、TypeScript。
- ❌ 重写视觉设计 / 换主题体系。
- ❌ 拆后端 / 改 API 语义。
- ❌ 做多平台前端。

## 2. 目标代码结构（无构建，经典脚本）

```
frontend/
├── index.html                 # 只留骨架 + 按顺序 <script defer src="/js/...">
├── style.css                  # 入口：@import 拆出的 6 个 css（或改成多个 <link>）
├── js/
│   ├── 00-util.js             # esc/fmt/$/api/sleep/uiZoom/剪贴板…
│   ├── 01-state.js            # 全局状态（SET/state/CC/COLLAB…）+ 安全 localStorage
│   ├── 02-shell.js            # boot、侧栏、顶栏、主题、缩放、banner/NOTIFY
│   ├── 10-chat.js             # 会话列表/消息渲染/流式/附件/翻页/导航/轨迹
│   ├── 11-engine.js           # 引擎/模型/模式/ACP agent/技能
│   ├── 12-asks.js             # 权限 / 表单 / 信任面板
│   ├── 20-collab.js           # 本地协作工作台 + 工作流画布 + 工坊（后续）
│   ├── 21-cocraft.js          # 群聊抽屉 + AI 成员 + 派活/对比/仲裁
│   ├── 30-code.js             # 编码模式 + 语法高亮 + run 终端
│   ├── 31-term.js             # 面板终端（PTY/SSE/ANSI）
│   ├── 40-music.js            # 音乐/歌词/频谱/播放条
│   ├── 41-visual.js           # 壁纸/落樱/外观/主题工坊
│   ├── 50-settings.js         # 设置/首次向导/更新/诊断
│   └── 99-boot.js             # 只调用各模块 init()（严格顺序）
└── style/
    ├── base.css  layout.css  chat.css  collab.css  cocraft.css  code.css  music.css  settings.css
```

**兼容策略（关键）**：拆文件时先保留**全局函数名**（`window.collabOpen = …` 等），
无头探针与 `check_features` 不用改；等全部拆完再逐步收敛到 `window.COCRAFT.*` 命名空间
（届时同步改探针，只改一次）。

**加载方式**：`<script defer src="/js/00-util.js?v=…">` 依次 14 个；不用 ES module
（避免改 `type=module` 后全局/顺序语义变化，测试也不用大改）。`defer` 保证顺序且不阻塞解析。

## 3. 分阶段实施

### 阶段 0：基线（0.5 天）
- 记录：首屏 `performance.mark`（脚本解析、首帧、首条消息）、长会话（500/2000 条）滚动帧率、空闲 5 分钟 CPU、内存。
- 把「页面隐藏 → 所有轮询暂停」与「窗口重新可见 → 恢复」做成统一 `VISIBILITY` 工具，先接上（风险极低）。
- 产出：`tools/fe_metrics.py`（读文件大小/函数数/间隔）+ 一段手动基线记录。

**验收**：基线数据留档；隐藏/恢复不报错。

### 阶段 1：拆文件（2~3 天，纯搬运不改逻辑）
- 按 §2 顺序切分；每切一个文件跑一次 `jsbalance` + `check_feature** + 相关无头回归。
- `index.html` 改 14 个 `<script defer>`；版本号仍是 `?v=`（每个文件都带同一个版本）。
- 先搬「低耦合」的：util/state/music/visual/term/code；最后搬 chat/collab/cocraft。
- 全局兼容：每文件 IIFE + 末尾 `window.xxx = xxx` 白名单；避免新增隐式全局。

**验收**：33+ 套回归全绿；`check_features` 0 缺失；页面行为无变化；单文件 ≤ 100 KB。

### 阶段 2：渲染与轮询（2~3 天，收益最高）
1. **消息渲染**：
   - `renderMessages()` 改为增量：首次全量，之后按 `time.created`/id 追加；删除/编辑才局部替换。
   - 长会话限制 DOM 节点（如 ≤ 800 条可见 + 上方「加载更早」已有分页），避免 2000 条全渲染。
   - 用 `DocumentFragment` + 一次 `append`；流式增量只更新当前气泡文本节点。
2. **轮询收敛**：
   - 统一 `POLL` 管理器：`register(name, ms, fn, {whenHidden:false})`；页面隐藏一律暂停（除 SSE 心跳）。
   - 频谱 70ms 只在「播放且可见」时跑；collab 1.5s 只在有活动 run 时跑（已如此，收进管理器）。
   - 合并 1s/2s/4s 的轻量刷新，避免同一帧多次读接口。
3. **热路径 DOM**：
   - 工作台 `collabTick` 已按节点 patch（好），把 `innerHTML` 全量重画的地方（成员 chip/列表）改成按 id 复用。
   - 高频状态用 `textContent`/`classList`，不重建节点。

**验收**：500 条会话首屏渲染 ≤ 150ms（本机基线对比）；隐藏 5 分钟 CPU 接近 0；滚动不掉帧；功能无回归。

### 阶段 3：弹层与状态（3~4 天，风险最高）
- 统一 `OVERLAY`：`open(id, {drawer|modal, onClose, focus})`，管理 z-index、Esc、遮罩、滚动锁、焦点归还。
- 现在各自为政的 `cfgOpen/ccOpen/agentsOpen/trustOpen/collabOpen/codeOpen/termOpen…` 改为注册到 OVERLAY（行为不变）。
- 状态：`state`/`CC`/`COLLAB` 逐步改成「store + subscribe」，渲染函数只读快照；先做 `COLLAB`（最独立）。
- localStorage：统一 `Store.get/set`（JSON + try/catch + 版本迁移），减少 85 处裸调用。

**验收**：任意两层弹层 Esc 只关最上面；关闭后焦点回到触发按钮；无重复监听/泄漏；回归全绿。

### 阶段 4：CSS（2 天）
- 按 §2 拆 8 个 CSS；`index.html` 多个 `<link>`（避免 `@import` 串行阻塞）。
- 用无头截图 + 选择器扫描找**未使用规则**（先报告，不盲删）；`!important` 从 18 降到 <10。
- 统一变量：间距/圆角/字号收敛到 `--space-* / --radius-* / --fs-*`（可选）。
- `content-visibility: auto` 用在长列表（消息、运行历史），减少离屏布局。

**验收**：视觉截图对比无差异；CSS 总量下降 ≥15%；首屏样式计算时间下降。

### 阶段 5：可观测与可求助（1 天）
- `window.onerror` / `unhandledrejection` → 顶部横幅 + `window.__lastError`（供诊断包读取）。
- 关键路径 `performance.mark/measure`：boot、首条消息、工作流首次渲染；只在 `localStorage.debug=1` 时输出。
- 接上「诊断包」（`docs/示例-诊断-工坊-方案.md` §2）：前端错误也进诊断。

**验收**：故意抛错能看到横幅且不白屏；诊断包含前端错误摘要。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 拆文件后加载顺序错 | 固定 `00…99` 前缀 + `defer`；每步跑回归；保留全局别名 |
| 全局函数被测试依赖 | 拆分阶段先不改名；最后统一命名空间时一次性改探针 |
| innerHTML 改动引入 XSS | 所有插值仍走 `esc()`；新增模板必须过 `md_render`/XSS 断言 |
| 轮询暂停导致状态过期 | 恢复可见时**立即补一次**；SSE 不受影响 |
| 弹层重构破坏工作台/编码抽屉 | 先做 OVERLAY 适配层（旧函数内部调用它），再逐个迁移 |
| CSS 拆分后主题覆盖顺序变 | 保持「基础 → 主题 → 组件 → 用户主题」顺序；截图对比 |
| 无构建无法 tree-shake | 以「文件级懒加载」替代：非首屏模块（音乐/编码/群聊）可延后到首次打开时再执行 init |

## 7. 建议的下一步

1. **先做 P0**（半天）：隐藏暂停 + 错误横幅 —— 立刻见效、零风险。
2. **再做 P1 拆文件**（2~3 天）：一次性把「改一个功能要翻 15k 行」解决。
3. **然后 P2 渲染/轮询**（2~3 天）：长会话与工作台体感最明显。
4. P3 弹层/状态、P4 CSS、P5 埋点按节奏跟进。

> 说明：本方案只做「结构 + 性能 + 一致性」，不改视觉风格；每一步都可独立交付、独立回滚。

### 8.2 与方案目标的偏差（如实记录）

| 目标 | 实际 | 原因 |
| --- | --- | --- |
| `!important` 18 → <10 | **✅ 6 处** | 移除 12 处「选择器特异性已经够」的多余写法；保留 4 处媒体查询 + `.cocraft [hidden]` + 图标槽（跨文件顺序 / 特异性确实需要） |
| `content-visibility: auto` | **✅ 加到 2 个安全列表** | 音乐主页歌曲行（`.mus-song`）+ 运行历史行（`.collab-run-row`），都配合 `contain-intrinsic-size`；**消息列表 / 轨迹页不加**（它们有 `scrollTop = scrollHeight` 依赖，AGENTS.md 记录过跳顶坑） |
| CSS 总量下降 ≥15% | 206270 → 207459 bytes（+0.6%） | 拆分有 ~1.3 KB 文件头开销；死代码仅几 KB。再降需大规模删未使用规则，误报风险高（**未强行达成**） |
| 统一变量 `--space-*` / `--radius-*` / `--fs-*` | 未做（可选） | 方案标注「可选」；大规模替换魔法数字有视觉回归风险，收益有限 |

### 8.3 检查结论

- 拆分 **0 遗漏**（函数 / 顶层声明对比拆分前备份）。
- OVERLAY **16 / 16 push-pop 配对**。
- XSS 抽查 11 个「innerHTML 裸变量插值」**全部安全**（已转义 / 数字 / 固定字符串）。
- 修复了 P2 的「编辑已有消息 + 同时新增」边界 bug（增量判断加入签名比较）。
- 既有 `fmtBytes` 重名（拆分前就有）保留：两实现仅 MB 小数位不同，30-code 覆盖 01-chat，行为与拆分前一致。

- 回滚方式：恢复备份 + 还原 `index.html` 的 `<script>` / `<link>`（或 git 恢复 `frontend/`）。
