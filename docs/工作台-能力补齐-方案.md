## 1. P1-A · 成员级 worktree 隔离

### 1.1 目标

每个成员一个独立工作目录；结果里显示「这个成员改了哪些文件」；避免并发成员互相踩文件。

### 1.2 现状（代码事实）

- `orchestrator.start_run()`（L1123）构造成员 `ms` 只有 `id/name/role/engine/permLevel/stage/...`，**没有 `cwd`**。
- `_run_member()`（L789）执行时：`cwd = str(run.get("cwd") or cfg_cwd or "")`，**所有成员同一个 cwd**。
- 因此「文件改动」只能按**任务**统计（`snapshots.changes_since_latest(root, scope)` 的 root 是任务目录）。

### 1.3 数据模型（新增字段）

工作流（`_collab_workflows.json`）：
```jsonc
{
  "isolate": true,                  // 可选：是否给每个成员独立工作目录（默认 false，保持旧行为）
  "members": [ { "id": "m1", "engine": "...", "role": "..." } ]
}
```

运行时 `run.members[i]`：
```jsonc
{
  "id": "m1",
  "workdir": "D:\\...\\runtime\\worktrees\\run_xxx\\m1",   // 隔离时才有；否则空
  "isolated": true,                                          // 是否真的隔离成功
  "isolationNote": "",                                       // 失败原因（如"非 git 且超过大小上限"）
  "changes": { "files": 3, "added": 1, "modified": 2 },      // 收尾时收集
  "changesDetail": [ { "kind": "modify", "path": "app.js" } ]
}
```

### 1.4 执行流程

1. `start_run()`：若 `isolate=true`，为每个成员准备目录。
   - **git 仓库**（`<cwd>/.git` 存在）：`git worktree add --detach <workdir> HEAD`（每个成员一个工作树，互不影响）。
   - **非 git**：`shutil.copytree(cwd, workdir, ignore=...)`（排除规则见 1.5）；超过大小上限（1.6）→ 不隔离，记 `isolationNote`。
2. `_run_member()`：`cwd = member.workdir or run.cwd or cfg_cwd`。
3. 成员完成后：`snapshots.changes_since_latest(member.workdir, scope)` 收集改动 → `member.changes / changesDetail`。
4. 收尾（run 结束 / 删除 run）：`git worktree remove --force <workdir>` 或 `rmtree`。
5. **默认不自动合并**回主目录；需要时用 `POST /orchestrate/merge`（见 1.7）。

### 1.5 非 git 拷贝的排除规则

```py
IGNORE = {".git", "node_modules", "runtime", "dist", "build", ".next", "target",
          "__pycache__", ".venv", "venv", "browser-profile", ".cache"}
# 另按文件后缀跳过：*.pyc *.log *.tmp 以及 > 8MB 的单文件（防止拷大视频）
```

### 1.6 大小上限

- 估算：先 `sum(文件大小)`（跳过 IGNORE），超过 `COCRAFT_ORCH_WT_MAX_MB`（默认 200 MB）→ **不隔离**，`isolationNote="工作区过大（>200MB），已退回共享目录"`，**UI 明说**（不假装隔离了）。
- git 仓库不受此限（worktree 不拷文件，只建索引）。

### 1.7 API / UI

| 变更 | 说明 |
| --- | --- |
| `POST /orchestrate/start` | 加 `isolate?: bool`（也可由工作流 `isolate` 决定） |
| `run.members[i].workdir/isolated/changes/changesDetail` | 回给前端 |
| `POST /orchestrate/merge {run, member?}` | **可选**：把一个成员的改动合并回主目录（git merge / 手动复制）；默认不提供一键合并，先只做「查看 + 手动」 |
| 工作流头 | 加「隔离」开关（检查器里，和工作流一起保存） |
| 结果列 | 「文件改动 · N 个」复用现有渲染；隔离失败时显示 `isolationNote` |

### 1.8 风险与取舍

1. **成员间依赖**：A 改的文件 B 看不到（各自独立目录）。阶段串行场景可接受（阶段等全部完成再进下一阶段）；**同一阶段内的并行成员互相看不到** —— 产品上必须写清楚。
2. **worktree 管理**：删 run 时忘删工作树会占盘 → 收尾统一清（`atexit` / 删除 run / 启动时扫残留）。
3. **大目录拷贝慢**：用排除规则 + 大小上限兜底（超限不隔离）。
4. **非 git 的"合并"**：没有版本控制，改动合并只能"人工看 diff + 手动复制"，**不自动合并**。

### 1.9 验收

- 两个成员同任务各改同一文件 → 各自 `workdir` 独立、结果列分别显示「改了 X」。
- 删除 run → 工作树/目录一起清掉。
- 非 git + 超大目录 → 不隔离、`isolationNote` 可见。
- 回归：`orchestrator_test` 新增「隔离目录独立 / git worktree / 非 git 拷贝 / 超限退回 / 收尾清理」。

### 1.10 工作量

**2~3 天**（后端为主：worktree 创建/收集/清理 + 测试；前端只加开关和「改动」展示）。

## 2. P1-B · 表单（elicitation）接待批

### 2.1 目标

agent 的 `session/request_elicitation`（问用户）进**待回答队列**，用户在 UI 回答后 agent 继续；超时自动 decline（fail-closed）。

### 2.2 现状（代码事实）

`orchestrator._auto_form(form, params)` 直接 `return {"action": "decline"}`，挂在 `svc.auto_form`。

### 2.3 数据模型

```jsonc
run.forms = [
  { "id": "f1", "member": "m2", "title": "选哪个方案", "created": 1792...,
    "fields": [ { "key": "plan", "type": "string", "title": "方案", "options": [...] } ],
    "status": "wait", "answer": null, "note": "" }
]
```

### 2.4 执行流程

1. `svc.auto_form = _ask_form(run, member, form)`：把表单加入 `run.forms`（status=wait），推 SSE/轮询可见，**阻塞等待**（与权限申请同一套机制）。
2. 用户在 UI 填写 → `POST /orchestrate/form {id, answers}` → 唤醒等待，返回 `{"action":"accept","content":answers}`。
3. 超时（`COCRAFT_ORCH_FORM_TIMEOUT`，默认 1800s）或取消 → `{"action":"decline"}`。
4. 结算后 `status=done/declined`，进历史。

### 2.5 API / UI

| 变更 | 说明 |
| --- | --- |
| `GET /orchestrate/forms?run=` | 待回答表单 |
| `POST /orchestrate/form {id, answers}` | 回答（accept） |
| 工作台 | 顶部「待回答 N」条 + 卡片（复用 `#ask` 的字段渲染：string / number / boolean / multiselect / `custom` 自由输入） |

### 2.6 风险

- 不同 ACP agent 的 elicitation 支持不一（codex 可能不发；openCode-acp 视情况）→ **不支持的就永远不会有表单**，不影响现有流程。
- 字段类型要覆盖 `custom`（自由输入），否则选项答不了"其他"。
- 超时必须 decline，否则 agent 侧会挂到 1800s。

### 2.7 验收

- agent 问「用哪个方案」→ UI 弹出卡片 → 填答 → agent 继续。
- 超时 → 自动 decline，不挂死。
- 回归：`orchestrator_test` 新增「表单进队列 / 回答 / 超时 decline / 取消 decline」。

### 2.8 工作量

**1~2 天**。

## 3. P2-A · 审计导出 CSV

### 3.1 目标

`collabExport` 增加「导出 CSV」：列 = 时间 / 成员 / 动作 / 命令原文 / 结果 / 决策；逗号与换行做 CSV 转义。

### 3.2 做法

- 前端 `collabExport(format)`：`json`（现状） / `csv`。
- CSV 字段：`time,run_id,member,action,command,decision,result`（**不含成员正文**，与 JSON 口径一致）。
- 转义：字段含 `,` / `"` / 换行 → 双引号包裹 + 内部 `"` 变 `""`。
- 文件名：`cocraft-audit-<run>.csv`。

### 3.3 验收

- Excel 能打开、字段完整、中文不乱码（UTF-8 BOM 可选）。
- 与 JSON 口径一致（不含正文）。

### 3.4 工作量

**0.5 天**。

## 4. P2-B · agent 侧会话收尾清理

### 4.1 目标

运行结束后删除 agent 内部会话（`opencode-acp` 会在共享库留一条），减少垃圾。

### 4.2 做法

- run 收尾（所有成员终态）后，对每个成员调 `AcpService.delete_session(member.sessionID)`（`service.py` 已有 `delete_session`）。
- **只删「本 run 内创建、标题含 `协作·` 标记」的会话**（`0.3` 起标题是 `协作·<name>`）—— 不确定就不删。
- 失败静默（不影响 run 结果）。

### 4.3 风险

- 误删 → 用标题/创建时间双重判断。
- 某些 agent 的 `session/delete` 不支持 → 忽略错误。

### 4.4 验收

- 跑完一个 run → agent 共享库里不再多出「协作·xxx」会话（或明确保留，记日志）。

### 4.5 工作量

**0.5~1 天**。

## 5. P3 · 运行历史自动裁剪

### 5.1 目标

`KEEP_RUNS` 启用：超过 N 条时删最旧的**已结束**记录（跑着的绝不删）。

### 5.2 做法

- `start_run()` 后：`runs` 超过 `KEEP_RUNS`（默认 200）→ 按 `created` 升序删最旧的 `done/failed/cancelled` 记录 + 其 `runs/<id>/` 目录 + 工作树。
- 删之前先确认不是当前选中 / 跑着的。

### 5.3 验收

- 造 205 条 → 自动删到 200；跑着的保留。

### 5.4 工作量

**0.5 天**。

## 8. 风险总表

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 成员间看不到彼此改动 | 同阶段并行会"各自为政" | 产品文案写清；阶段串行天然规避 |
| 大目录拷贝慢/占盘 | 非 git 隔离卡住 | 排除规则 + 200MB 上限 + 超限退回并明说 |
| worktree 残留 | 占盘 | 收尾/删除 run/启动扫残留 |
| elicitation 超时 | agent 挂 1800s | 默认 1800s 后 decline，fail-closed |
| 误删 agent 会话 | 丢历史 | 只删「本 run + 协作·标题」；不确定不删 |

---

> 一句话：**先把「共享工作区」拆掉（worktree）让结果可信，再补「agent 能问人」（elicitation），CSV 和清理是小收尾。**
