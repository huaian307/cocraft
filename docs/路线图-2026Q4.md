# cocraft 后续发展计划（2026-10-22 起）

> 这份计划把「竞争力评估 → 付费理由 → 竞争地图」的结论落成**可执行、可放弃**的路线。
> 原则：**先让产品存在，再让差异被看见，最后才谈收费。**
> 时间估算按「单人、每天 3~4 小时」折算（1 人日 ≈ 3~4h）。

---

## 0. 一句话定位（从此收敛，不再摇摆）

> **Windows 本地、跨厂商、可撤回、可审计的 AI 护栏层。**
> 不卖「更会写代码的 agent」，卖「**敢让它动你电脑**」。

三个关键词，任何一个丢了，这个项目就退化成「又一个多 agent 面板」：

| 词 | 含义 | 反例（丢了这个词会变成什么） |
| --- | --- | --- |
| **Windows 本地** | 不登录、不上云、自带 Key、数据不出机 | 又一个云端 Agent 平台 |
| **跨厂商** | OpenCode + codex + claude + opencode-acp + dsh 同台 | 又一个 Claude Code 皮肤 |
| **可撤回 / 可审计** | 整工作区快照 + 破坏性先隔离 + 命令原文 + 审批证据 | 又一个并行终端看板 |

## 1. 当前基线（事实，不美化）

| 项 | 现状 |
| --- | --- |
| 本地版本 | `ui 0.2.62`（审计链 + 圣烛教堂主题 + 壁纸中心 + 更新器修复） |
| 线上最新 | **`v0.2.62`**（Latest，2026-10-25 发布）—— `0.2.14`~`0.2.62` 一并发布 |
| 已推送 | `main` `128b033` + tag `v0.2.62`（工作树干净） |
| 质量 | `check_features` **2046 项 / 缺失 0**、`run_suite` **42 套全绿**、仍无真实用户反馈 |
| 法务 | **没有 LICENSE 文件**（"开源"目前在法律上是空的） |
| 能力短板 | worktree 隔离没做、模板库/4 步向导没做、上手成本高、Windows only、单人维护 |

**结论：技术存量够用，产品化停在"我这儿能跑"。**

## 2. 不做清单（写死，防止战线扩散）

1. **不做通用多 agent 编排竞赛** —— Conductor / Vibe Kanban / Antigravity / Claude Code agent teams 已经卷到这里，且 Vibe Kanban 产品已日落。编排降级为**功能**，不是卖点。
2. **不做云端 / 企业合规平台** —— SOC2、RBAC、SSO、EU AI Act 证据链是大厂和 Endor Labs / Knostic 的战场，单人进不去。只做「小团队可审计」。
3. **不做多平台** —— macOS/Linux 有免费开源竞品，Windows 是空的。**先吃透 Windows**，别分兵。
4. **不做跨机协同**（2026-10-22 拍板）—— 远程执行 / 云沙箱（Codex 云端、Cursor Background Agents、OpenHands、Ona、Northflank、E2B 等）和协议层（A2A：Linux Foundation、150+ 组织、生产部署）都已成熟；完整跨机协同会正面撞云厂商，还会把"本机可撤回"的定位稀释成"网络责任"。
   - 只保留两个窄口：**① 工作流 / 策略 / 审计的导出导入**（文件级，跟着 P1 的审计导出一起做，零网络代码）；**② 远程执行成员（SSH）** —— 门票：有 **≥3 个付费团队**明确要"多台机器 / Linux 构建机"，才立项（P5）。

另外：**主题 / 壁纸 / 音乐 / 任意外观不再投入**（它们是"喜欢"，不是"必须"）。

---

## 3. 竞争结论 → 战略选择

| 层 | 谁在做 | 我们能占的缝 |
| --- | --- | --- |
| 多 agent 工作台 | Conductor（macOS 闭源）、Vibe Kanban（日落）、Nimbalyst、Claude Squad、Sculptor | **Windows 原生桌面** + 不依赖 git（不是所有目录都是仓库） |
| 撤销 / 检查点 | Claude Code `/rewind`、Cline、Cursor、Aider | 官方明确**不覆盖 shell 命令 / 子 agent 编辑 / 符号链接**；**Codex 没有 rewind** → 我们覆盖「整工作区 + shell 删除 + 隔离区」 |
| 权限审批 | Claude Code permissions、Codex 审批 + 沙箱、Cline | **分级 trust + fail-closed（范围未知就问）+ 破坏性永不自动 + 拥有者专属批准** |
| 企业治理 / 审计 | Codex Enterprise、Endor Labs、Knostic | 「**给甲方看的证据链**」（谁批的、命令原文、隔离区清单、可导出） |

**战略选择：做"缝合位"。** 每层都有人做，但没人把这四层缝在一个 Windows 本地桌面里，且以"可撤回"为第一性。

⚠ 窗口期：Claude Code 补上 shell 级 checkpoint、Codex 补 rewind、Conductor 出 Windows 版 —— 任意一条发生，空档都会变窄。**所以 P0 发布不能拖。**

## 4. 路线图（四个阶段 + 一个有条件阶段）

### P0 · 让产品存在（3~5 人日，"本周"）

| 交付物 | 完成定义（DoD） |
| --- | --- |
| 本地提交 `0.2.21` | `git status` 干净、`check_features` 0 缺失 |
| 打包 + VM 验证 | `dist\cocraft-setup-0.2.21-windows-x64.exe` 在干净 VM 装得上、起得来、能对话 |
| **LICENSE** | 选定并落地（建议 **AGPL-3.0** 或 **BSL 1.1**，见 §7） |
| CHANGELOG + Release notes | `0.2.14`~`0.2.21` 一次补齐（现在停在 0.2.13） |
| push + tag + Release | GitHub 上 `v0.2.21` 可下载，资产 SHA256 对得上 |
| **1 个入门模板（实现 → 审查）** | 模板可一键导入；画布出现成员/阶段；改目录 + 写任务就能跑（见 `docs/工作流上手-方案.md`） |
| **5 分钟 demo** | 脚本 + 录屏：**选模板 → 跑**（3 个 agent 干活）→ 1 条命令审批 → 1 次破坏性进隔离区 → 一键回退 |
| **对比文** | 《Claude Code /rewind 覆盖不到的 3 件事》—— 蹭已验证需求，指出官方限制 |

**验收**：一个陌生人拿到链接，5 分钟内能看到"撤回"这一下。
**放弃条件**：不放弃。这是唯一不可省略的阶段。

---

### P1 · 把「护栏层」做实（8~12 人日，2~3 周）

| 交付物 | 为什么是它 | DoD |
| --- | --- | --- |
| **成员级 worktree 隔离** | 多 agent 落地最真实的痛点："谁改了什么" | 每个成员独立 worktree；结果页显示分支/改动归属；`orchestrator_test` + 新增回归 |
| **审计导出（CSV / JSON）** | 唯一能被甲方看见的付费物 | 导出含：任务/成员/审批人/命令原文/时间/隔离区条目；字段稳定、有列头 |
| **破坏性操作覆盖补强** | Codex 不报路径 → 现在靠"从命令原文猜"；漏了就等于没保护 | `guess_targets` 覆盖常见 shell 删除/移动；猜不到时**明确告知"本次未能预先隔离"**并进审计 |
| **恢复演练** | 能撤回 ≠ 撤回过 | 一个自动化脚本：删除 → 隔离 → 恢复 → 校验内容逐字节一致（已有 `quarantine_test`，扩成端到端） |
| **失败诚实** | 护栏产品的底线是"不骗人" | 所有"没保住"的路径都有红字 + 审计记录（已有，扩到新场景） |

**验收**：一条真实任务里，"三个 agent 各改一个文件 → 回到任一 agent 之前"能一键完成，且导出材料能给别人看。
**放弃条件**：如果 5 个试用者里没人关心"归属"，worktree 降级为可选，别硬做。

---

### P2 · 降低上手成本：**5 分钟搭一套流程**（5~7 人日）

> 方案见 **`docs/工作流上手-方案.md`**（L0 模板 → L1 向导 → L2 画布 → L3 分享）。

| 交付物 | DoD |
| --- | --- |
| **模板库 3~5 个**（L0） | 一键导入；导入自检（agent/模型/阶段/权限）；首跑成功率 ≥80% |
| **4 步向导**（L1） | 目标 → 成员 → 权限 → 目录/任务；一路回车也能跑 |
| **导入 / 导出 `.cocraft-workflow.json`**（L3） | 换台机器导入后能跑；重名自动加后缀；版本不兼容明确报错 |
| **成本护栏**（先 `maxRounds`） | 运行前显示预计轮次；超限停止而不是继续烧 |
| 首次 3 步向导（已有雏形） | 装完 → 填 Key → 建第一个工作流，**全程不需要看文档** |
| 诊断包（`__diagnostics()` 已有） | 一键导出 zip：版本/引擎/agent/权限/最近错误/日志尾部（脱敏） |
| 错误人话化 | 常见 8 类失败（无 Key / agent 缺失 / 模型失效 / 端口占用 / 权限拒绝 / 快照失败 / npm 失败 / 引擎未连接）都有"下一步做什么" |
| SmartScreen 说明 | 未签名包的安装说明写清楚（签名暂缓已拍板） |

**验收**：找一个非本项目的人，**不提问**的情况下 10 分钟内完成"选模板 → 跑 → 审批 → 回退"。

---

### P3 · 付费验证（8~12 人日，与真实用户并行）

> 模式与功能切分见 **`docs/商业模式-开源与团队版.md`**（个人免费含全部安全能力；团队版卖汇总/策略/证据/支持）。
> **首个付费功能只做一个**（三选一），验证到人再扩。

| 交付物 | DoD |
| --- | --- |
| **首个付费功能（三选一）** | 多成员汇总 / 集中策略 / 签名审计导出 —— 只做一个，且必须被 3 个试用团队实际用到 |
| 团队策略模板 | 按项目/角色预设权限（只紧不松），可导入导出 |
| 审计导出增强 | 按任务/时间/成员筛选；一页 PDF 摘要（可选）；**哈希链校验脚本**（免费版也有链） |
| 授权与试用 | 离线签名 license（席位 / 到期 / 试用 14 天）；**到期只读、不删数据**；**不做账号体系** |
| 3 个真实团队试用 | 每个团队跑一个真实小项目，收集"愿不愿意付"的答案 |
| 服务化套餐 | 「AI 安全落地」服务（装 + 策略 + 演练 + 审计模板），¥3,000~8,000/次 |

**验收（Go/No-Go）**：3 个团队里 **≥2 个**说"愿意付"（服务单也算）。
**放弃条件**：3 个都只夸不买 → 停掉团队版开发，保持"个人免费 + 服务接单"，不硬做订阅。

## 5. 版本节奏

| 版本 | 内容 | 备注 |
| --- | --- | --- |
| `0.2.21` | npm agent 自主更新（已完成，待发布） | 本轮 |

发布纪律（每次都要）：
1. `check_features` 0 缺失 + `run_suite` 全绿；
2. 前端 bump `?v=`（11 script + 8 link 统一）；
3. 后端改动 → 重启 8787 并核对 `pid` / `uptime`；
4. 干净 VM 装一次（覆盖升级路径也要走一遍）；
5. 推送 + tag + Release + 桌面安装包同 SHA256。

## 6. 验证门（别再自嗨）

| 指标 | 观察方式 | 及格线 |
| --- | --- | --- |
| 能不能被看懂 | 5 分钟 demo 录屏的完播 / 反馈 | 3/5 的人能复述"它能撤回" |
| 能不能被用起来 | 陌生人试用 | 10 分钟内完成"派活 → 审批 → 回退" |
| 有没有人要 | 访谈（只找外包/小团队） | 10 人里 ≥3 人说出具体事故成本 |
| 愿不愿付 | 报价测试（服务先行） | 3 个团队里 ≥2 个掏钱或明确预算 |
| 留存 | 两周后是否还用 | ≥1/3 的试用者第二周还打开 |

**任何一项长期为 0，就说明方向错了，别加功能，先改定位。**

## 7. 风险清单与对策

| 风险 | 概率 | 对策 |
| --- | --- | --- |
| 上游把能力吃掉（Claude Code 支持 shell checkpoint / Codex 加 rewind） | 中高 | 主打**跨厂商整合 + Windows + 审计证据**，这三点上游结构上不会做全 |
| 单人维护撑不住（35 套回归 + 双端） | 高 | 收敛平台（只 Windows）、冻结非核心模块、把回归做成 CI 一键 |
| 发布一直拖（最大风险） | **高** | P0 设为**唯一不可跳过**的阶段，其它阶段都为它让路 |
| 签名/杀软误报 | 中 | 短期：SHA256 + SmartScreen 说明；中期：OV 证书；不承诺做不到的事 |
| 许可证缺失导致"开源"无效 | 高 | P0 内落地 LICENSE（**AGPL-3.0**：防止被闭源白嫖；**BSL 1.1**：允许自用、限制商用托管，2~4 年后转 Apache） |
| 第三方 agent 的许可证/条款（codex / claude / opencode 适配器） | 中 | 不随包分发受限组件；安装时由用户自己 npm 装（现在就是这么做的，保持） |
| 用户数据事故（我们自己的 bug） | 低但致命 | 隔离区/快照默认策略、恢复前不覆盖、失败必红字；发布前跑恢复演练 |
