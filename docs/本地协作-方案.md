# 本地协作（单机多 Agent 工作台）· 方案

> 状态：**Runner + 工作台 UI 均已落地（2026-10-19，`ui 0.2.1`）**。
> 目标：把「多智能体派活 / 对比 / 仲裁」从**群聊消息**里解耦出来，**不需要登录、不经过云端**。

## 0. 为什么做

当前多智能体编排在群聊里：必须先登录 cocraft、建群、拉 AI 成员，才能派活。
这和「单机、本地、数据不出机」的定位矛盾。

**原则**：本机编排是默认；群聊保留为**可选的多人 / 多设备协作层**。

## 1. 分层

```
┌─────────────────────────────┐
│ 工作台 UI（下一刀）          │  任务 / 成员 / 结果列 / 对比 / 仲裁
└──────────────┬──────────────┘
               │ HTTP /orchestrate/*
┌──────────────▼──────────────┐
│ orchestrator.py（已落地）    │  任务 / 成员 / 并发 / 权限队列 / 取消 / 仲裁
└──────────────┬──────────────┘
               │ 每个成员独立 AcpService + 独立会话
┌──────────────▼──────────────┐
│ ACP agent 子进程（本机）      │  codex / claude / opencode / dsh …
└─────────────────────────────┘
```

群聊（`cocraft_agents`）与本地协作**互不依赖**；未来都接同一个 `Room` 抽象。

## 2. 数据模型

`runtime/state/_orchestrator/runs/<run_id>.json`：

```jsonc
{

  "task": "把登录拆成独立模块",
  "cwd": "D:/ws",
  "status": "running|done|partial|failed|cancelled",
  "created": 0, "updated": 0,
  "members": [{
    "id": "m1", "name": "实现者", "role": "implementer", "roleLabel": "实现者",
    "engine": "opencode-acp", "status": "wait|running|done|failed|timeout|cancelled",
    "output": "", "error": "", "sessionID": "",
    "tokens": {}, "context": null,
    "activities": [{ "ts": 0, "kind": "tool|permission", "name": "", "status": "" }],
    "kind": "member|arbitration", "cancelled": false
  }],
  "permissions": [{ "id": "operm_…", "member": "m1", "memberName": "",
                    "kind": "execute", "title": "Run command", "command": "",
                    "locations": [], "destructive": false,
                    "status": "pending|allowed|denied|timeout", "decision": "once|always|reject",
                    "created": 0, "decidedAt": 0 }],
  "arbitration": { "member": "arb", "status": "running|done|failed", "pick": "方案B" }
}
```

## 3. Runner 行为

- **每个成员独立 `AcpService` + 独立会话文件**（`<run>/<member>.sessions.json`），不碰
  面板/群聊的 `_acp_sessions.json`。
- **并发**：每个成员一个线程；单成员失败/超时不影响别人。
- **超时**：`COCRAFT_ORCH_TIMEOUT`（默认 600s）；超时 `interrupt` 并标 `timeout`。
- **取消**：`/orchestrate/cancel {id, member?}`；`interrupt` 后标 `cancelled`。
- **结果**：文本 / tokens / context / 工具活动；`run.status` 汇总 done/partial/failed。
- **落盘**：开始、成员状态变化、权限结算、结束时写入；`get_run` 内存优先，缺失回读磁盘。

## 4. 权限（与面板同一份等级）

- 命中 `allowed_by_level` → 自动 `once`（联网独立能力；破坏性**永不自动放行**）。
- 否则进入**任务级待批队列**：`GET /orchestrate/pending?run=`，`POST /orchestrate/permission {id, decision}`。
- 超时（`COCRAFT_ORCH_ASK_TIMEOUT`，默认 180s）或取消 → **拒绝**（fail-closed）。
- 选择「始终允许」→ 写入 ACP 的 `_acp_always.json`（与面板同一条记忆）。
- **表单（elicitation）**：第一刀自动 decline（避免静默挂 1800s）；后续接待批队列。
- **0.2.13 起：成员级权限 `permLevel`**（`""` 跟随面板 / `ask` / `read` / `edit` / `exec` / `trust`）——
  `trust` 只放开**非破坏性**（读/写/执行/联网），**破坏性仍然必须人确认**（放行前仍先进隔离区）；
  改动立刻生效，但**已挂起的申请不会自动放行**（仍要拍板）。

## 5. HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/orchestrate/catalog` | agent 清单（可用性）+ 角色 + 团队预设 |
| POST | `/orchestrate/start` | `{task, cwd?, members:[{engine,name,role}]}` |
| GET | `/orchestrate/run?id=` | 任务详情（成员 / 权限历史 / 仲裁） |
| GET | `/orchestrate/runs` | 最近任务列表 |
| GET | `/orchestrate/pending?run=` | 待批权限 |
| POST | `/orchestrate/cancel` | `{id, member?}` |
| POST | `/orchestrate/member` | `{run, member, permLevel}` · 运行中改成员权限（只影响下一条申请） |
| POST | `/orchestrate/permission` | `{id, decision: once/always/reject}` |
| POST | `/orchestrate/arbitrate` | `{id, engine, name?}` → 再跑一个 reviewer |
| POST | `/orchestrate/delete` | `{id}` → 删除**已结束**的运行记录（JSON + 成员会话文件；跑着的先取消） |

## 6. 已知限制（第一刀）

- ~~**没有 UI**（第一刀时的状态）~~ → **0.2.1 起已交付工作台 UI**；`0.2.11` 加工作流画布，`0.2.13` 加节点级权限。
- **文件改动按"任务"级别**：并发成员共享工作区，无法可靠归属到某个人；
  需要真正的"每人一列改了什么"时，要用 worktree / 独立工作目录。
- **表单自动拒绝**（见上）。
- **agent 侧会话未自动清理**（opencode-acp 会在共享库里留下一条会话）——`0.2.6` 起「接续」列表默认把它归到「内部会话」标签里，不再和项目会话混排；后续可加收尾删除。
- 运行历史不做自动裁剪（`KEEP_RUNS` 仅预留）。

### 7.4 新建任务

1. 任务文本（多行）。
2. 工作目录（默认当前会话目录；可清空 = agent 默认）。
3. 成员行：`角色下拉（4 个 / 无） + 名字 + 引擎下拉（catalog 可用）`，可增删（1~8）。
4. 预设：`GET /orchestrate/catalog` 的 `presets`（dev / review / research）→ 一键填成员。
5. 「开始」→ `POST /orchestrate/start`；成功后选中新任务并开始轮询。

### 7.5 运行详情 / 轮询

- 打开任务后每 **1.5s** `GET /orchestrate/run?id=`（运行中），完成即停；切走 / 关闭页面停止。
- 每个成员列：
  - 状态 chip：等待 / 运行中 / 完成 / 失败 / 超时 / 已取消
  - Markdown 输出（复用 `renderText`）
  - `tokens` / `context`（复用 `fmtTok`）
  - 工具活动（复用轨迹页 `TOOL_META` 的中文摘要，最多显示 N 条）
- 任务头：`取消全部` / 单成员 `取消`；完成后 `重跑`（同成员再开一个 run 或同 run 追加）。
- 错误：成员 `error` 红字；整体 `partial/failed` 明说哪些失败。

### 7.6 待批权限（关键）

- 来源：`run.permissions` 中 `status=pending`（或 `GET /orchestrate/pending`）。
- 一张卡片：
  - `🔐 <成员名> 请求：<title>` + **命令原文**（等宽，超长省略）
  - 破坏性 → 红字「破坏性操作」+ 按钮变「确认执行」
  - 按钮：**允许一次 / 始终允许 / 拒绝**
- 点击 → `POST /orchestrate/permission {id, decision}`；**逐条**，没有全放行。
- 倒计时（`ASK_TIMEOUT` 180s）到点自动拒绝，卡片变「已超时」。
- 与信任面板共用同一套「待批 / 历史」展示；不另造审计语义。

### 7.7 对比 / 逐行差异 / 仲裁

- `对比`：≥2 个成员完成才出现 → 复用现有 `#cmp` 风格（每人一列）。
- `逐行差异`：正好 2 人时可用（复用 `ccDiffLines` / `renderDiff`；太长不算）。
- `请审查者仲裁`：
  - 只列 catalog 中可用 agent（默认选角色=reviewer 的成员，没有就让用户选）；
  - `POST /orchestrate/arbitrate {id, engine, name}`；
  - 结果卡显示 Markdown + 抠到「推荐 X」高亮（复用 `ccArbPick` 正则）。
- 结论写入运行记录（`arbitration.pick`），供信任面板历史复用。

### 7.8 历史与审计

- 历史列表：任务 / 时间 / 状态 / 成员数；点击只读查看（可重跑）。
- 信任面板接入：
  - 运行时间线（开始/完成/取消/失败）
  - 审批历史（哪条申请、谁批准、什么时候、命令原文）
  - 审计导出（JSONL/CSV，脱敏）
- 遵循 `docs/产品化与竞争力评估.md` 的红线：只读展示、逐条操作、复用现有接口。

## 8. 安全不变量

- 不放「一键全放行」；权限逐条。
- 破坏性操作永远要确认（即使等级 all）。
- 本地协作不把任务/结果发给任何云端。
- 每个任务独立目录；不覆盖面板/群聊会话文件。

> 本节只列**工作台本身**还差的事；发布链路 / 示例 / 诊断 / 工作流工坊属于「产品化」层，不混进来。
>
> **详细施工方案**（本节是摘要，细节看这两份）：
> - **工作台能力补齐**（worktree / elicitation / CSV / 清理）→ **`docs/工作台-能力补齐-方案.md`**

### 9.1 现状（已交付）

- 工作台 UI：任务 / 成员列 / 结果 / 对比 / 逐行差异 / 仲裁 / 待批权限逐条 / 取消 / 重跑 / 审计导出。
- **工作流画布**：可复用工作流 + 项目分组 + 节点连线 + 快速开跑 + 阶段串行（实现 → 审查 → 测试）+ 条件/失败策略/重试 + 归档/另存 + 快捷键/引导。
- **节点级权限**：`permLevel`（跟随面板 / ask / read / edit / exec / **trust**）；`trust` = 非破坏性自动、破坏性仍确认。

### 9.2 待做清单（按优先级）

| 优先级 | 项 | 现状（代码事实） | 价值 |
| --- | --- | --- | --- |
| **P1** | **成员级 worktree 隔离** | `start_run` 里所有成员共用同一个 `cwd`；「文件改动」只能按**任务**统计，无法归属到某个成员 | 让「每人改了哪些文件」可信；避免并发成员互相踩文件 |
| **P1** | **表单（elicitation）接待批** | `orchestrator._auto_form` 直接 `return {"action":"decline"}`（避免静默挂 1800s） | 补齐「人在环」最后一环：agent 问用户能真正回答 |
| **P2** | **审计导出 CSV** | `collabExport` 只导 `application/json` | 便于外部分析 / 留档 |
| **P2** | **agent 侧会话收尾清理** | 运行结束不删 agent 内部会话（`0.2.6` 起只是在「接续」列表归到「内部会话」标签） | 减少共享库垃圾 |
| **P3** | 运行历史自动裁剪 | `KEEP_RUNS` 仅预留，未启用 | 长期磁盘 |

### 9.3 各项施工方案

#### P1-A · 成员级 worktree 隔离（最有价值）

- **目标**：每个成员一个独立工作目录；结果里能显示「这个成员改了哪些文件」。
- **做法**：
  1. `start_run`：为每个成员准备目录 —— git 仓库用 `git worktree add runtime/worktrees/<run>/<member> <branch>`；非 git 用 `copytree`（排除 `node_modules / .git / runtime / dist` 等重目录）。
  2. 每个成员的 `AcpService` 用该目录作 `cwd`（而不是共用 `cwd`）。
  3. 成员完成后：`snapshots.changes_since_latest()`（或 `git diff --stat`）收集该目录改动 → 写进 `member.changes`。
  4. UI：结果列每列显示「文件改动 · N 个」（复用现有详情渲染）。
  5. 收尾：可选「一键合并回主目录」（git merge / 手动），**默认不自动合并**。
- **风险 / 取舍**：
  - 非 git 仓库 copytree 慢（大目录）→ 用排除规则 + 大小上限；超过上限就退回共享 `cwd` 并**明说**。
  - 成员间「依赖」（A 改的文件 B 看不到）→ 阶段串行场景可接受（阶段等全部完成再进下一阶段）；**同一阶段内的并行成员互相看不到**，需要产品上明确。
  - worktree 清理（运行结束 / 删除 run 时删工作树）。
- **验收**：两成员同任务各改同一文件 → 各自目录独立、结果列分别显示「改了 X」；删除 run 时工作树一起清掉。

#### P1-B · 表单（elicitation）接待批

- **目标**：agent 的 `session/request_elicitation`（问用户）进**待回答队列**，用户在 UI 回答后 agent 继续。
- **做法**：
  1. `orchestrator` 新增 `_ask_form(run, member, form)`：把表单塞进 `run.forms`（含 id / 字段 / 倒计时），**不自动 decline**。
  2. 新增 API：`GET /orchestrate/forms?run=`、`POST /orchestrate/form {id, answers}`。
  3. UI：工作台加「待回答 N」卡片（复用 `#ask` 的字段渲染：string / number / boolean / multiselect / `custom`）。
  4. 超时（`COCRAFT_ORCH_FORM_TIMEOUT`，默认 1800s）或取消 → **decline**（fail-closed）。
- **风险**：不同 ACP agent 的 elicitation 支持不一（codex 可能不发）；字段类型要覆盖 `custom` 自由输入。
- **验收**：agent 问「用哪个方案」→ UI 弹出 → 填答 → agent 继续；超时自动 decline 且不挂死。

#### P2-A · 审计导出 CSV（小改动）

- **做法**：`collabExport` 增加「导出 CSV」：列 = 时间 / 成员 / 动作 / 命令原文 / 结果 / 决策；逗号与换行做 CSV 转义。
- **验收**：Excel 能打开、字段完整（不含成员正文，与 JSON 口径一致）。

#### P2-B · agent 侧会话收尾清理

- **做法**：run 收尾时，对 `opencode-acp` 这类「共享库会留会话」的 agent，调 `AcpService` 删除/标记内部会话（`0.2.6` 的内部会话标签可复用做判断）。
- **风险**：误删 → 只删「本 run 内创建、且标题含 `collab` 标记」的会话，**不确定就不删**。

#### P3 · 运行历史自动裁剪

- **做法**：`start_run` 时若 `runs` 超过 `KEEP_RUNS`（默认 200），删最旧的**已结束**记录 + 其工作树/会话文件；跑着的绝不删。

### 9.4 建议顺序

1. **P1-A worktree 隔离**（解决「共享工作区」这个根本限制，价值最大）。
2. **P1-B elicitation 接待批**（补齐人在环；和权限队列同一套交互）。
3. **P2-A CSV 导出**（0.5 天，顺手做）。
4. **P2-B 会话清理 + P3 历史裁剪**（维护性，穿插做）。

### 9.5 明确不做（需另立方案）

- **任意 DAG / 子工作流 / 富条件表达式 / 阶段级超时 / 与技能模板联动** —— 方案里明确排除，不是漏做。
- 工作流工坊（模板分发）—— 属于「生态/产品化」层，见 `docs/示例-诊断-工坊-方案.md`。
