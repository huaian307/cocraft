## 1. 用户问题（原话拆解）

1. **每次用工作台都要「新建任务」** —— 成员（角色/名字/大脑）每次重选一遍，太麻烦。
2. **看不到「工作流」** —— 左栏只有一条条运行记录，没有"这个项目有哪几套常用打法"的概念。
3. **希望参考 LibTV 那种画布** —— 用节点 + 连线把工作流看成一个可编辑的图；
   并且**同一工作流的任务可以简化布置**（不用每次走完整的新建流程）。

一句话：**从「一次性任务」升级成「可复用的工作流 + 画布」**。

---

## 2. 现状与根因（代码对齐）

| 层 | 现状 | 问题 |
| --- | --- | --- |
| 数据 | `orchestrator.start_run(task, cwd, members)` 只产出 **run**；`runtime/state/_orchestrator/runs/<id>.json` 存单次运行 | 没有「工作流」实体，成员配置用完即弃 |
| 接口 | `/orchestrate/start`、`/runs`、`/run`、`/cancel`、`/permission`、`/arbitrate`、`/delete` | 没有工作流 CRUD |
| UI | 顶栏「＋ 新建任务」→ 弹窗（任务/目录/成员行/预设）→ 启动 | 每次都要走弹窗；成员只能靠预设或手填 |
| 左栏 | 运行历史（已带项目徽章 + 按项目筛选，`0.2.9`） | 有"项目"，但**没有"工作流"层**；多条 run 之间看不出是同一套打法 |
| 执行 | 一条任务 → N 个成员**并行**（服务端按 mentions 各推） | **不是任意 DAG**；画布 v1 不能假装支持串行依赖 |

> ⚠ 关键事实：当前执行模型是 **扇出（fan-out）**，不是工作流引擎。
> 画布 v1 是「**可视化编辑器 + 启动器**」，连线由角色关系**推导**，不是用户随意画的执行依赖。
> 真正的「串行阶段 / 条件分支」属于 **P4（另立方案）**，本方案不做。

## 3. 目标与非目标

### 目标（本方案）

- **工作流（workflow）成为一等公民**：一套成员 + 默认任务 + 项目目录 + 画布布局，可反复运行。
- **不再每次新建任务**：工作流上一键运行（可临时改任务），从运行页「再跑一次」。
- **画布可视化**：任务节点 + 成员节点 + 审查/仲裁节点 + 连线；可拖拽、可增删成员、可缩放，布局落盘。
- **运行与工作流关联**：每条 run 记录 `workflowId`（历史兼容：没有的归"未归属"）。
- **运行状态可见**：画布上节点直接显示 等待/运行/完成/失败；点节点看结果。
- **零新依赖**：纯原生 JS + SVG/CSS transform（项目无构建步骤）。

### 非目标（明确不做 / 以后再说）

- ❌ 任意 DAG 执行（串行阶段、条件分支、重试编排）→ P4 单独设计。
- ❌ 云端 / 多人协作 / 账号体系（本项目定位是单机、不上云）。
- ❌ 在画布里直接写代码 / 内嵌编辑器（点节点跳现有结果列/编码模式即可）。
- ❌ 自动生成工作流（AI 自动编排）—— 先把手动工作流做扎实。

## 4. 产品模型（三层）

```
项目（cwd，已有）            D:\work\proj-a
└── 工作流（新增）           登录重构（codex 实现 + codex 审查 + mock 测试）
    ├── 成员：角色 / 名字 / 引擎
    ├── 默认任务模板（可留空）
    ├── 画布布局（节点坐标 / 缩放）
    └── 运行（已有）          run_20261022-...（保存成员快照 + workflowId）
```

- **工作流是模板，运行是快照**：改工作流成员**不会**改历史 run（旧 run 保留当时的成员与结果）。
- **项目 = cwd**（与 `0.2.9` 的项目徽章/筛选同源）；工作流默认继承项目的 cwd，也可单独指定。
- 旧 run 没有 `workflowId` → 在左栏归到「未归属运行」；提供「另存为工作流」（P3）。

## 5. 数据模型

`runtime/state/_collab_workflows.json`（新文件，不进 git）：

```jsonc
{
  "version": 1,
  "workflows": [
    {
      "id": "wf_20261022-101500_ab12cd",
      "name": "登录重构",
      "cwd": "D:/work/proj-a",
      "taskTemplate": "把登录拆成独立模块，保持旧接口",   // 可空
      "members": [
        { "id": "m1", "role": "implementer", "name": "impl", "engine": "codex-node" },
        { "id": "m2", "role": "reviewer",    "name": "rev",  "engine": "opencode-acp" }
      ],
      "layout": {
        "zoom": 1,
        "nodes": { "task": {"x": 40, "y": 160}, "m1": {"x": 360, "y": 90},
                   "m2": {"x": 680, "y": 90}, "arb": {"x": 960, "y": 90} }
      },
      "created": 1792636800000,
      "updated": 1792636800000,
      "lastRunId": "run_20261022-102000_9f8e7d",
      "runCount": 3
    }
  ]
}
```

run JSON 增字段（`start_run` 写入、`list_runs` 返回）：

```jsonc
{ "workflowId": "wf_...", "workflowName": "登录重构" }
```

- 成员 id 在 **工作流内**稳定（`m1..mN`），run 再复制一份（保持现有 `members[].id` 语义）。
- 画布坐标只存 `{x,y}`（设计像素），缩放单独存；**不存像素宽高**（自适应）。
- 上限沿用：成员 ≤ 8；名称清洗同 `start_run`（`[A-Za-z0-9_-]` 才可 @）。

## 6. API 设计（全部挂 `/orchestrate`，本地、无鉴权）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/orchestrate/workflows?cwd=` | 工作流列表（按 `updated` 倒序；`cwd` 可选过滤） |
| POST | `/orchestrate/workflows/save` | `{id?, name, cwd, taskTemplate?, members[], layout?}`；无 id = 新建 |
| POST | `/orchestrate/workflows/delete` | `{id}`；**不删任何 run**，只解除关联（run 里保留 `workflowName` 快照） |
| POST | `/orchestrate/workflows/duplicate` | `{id, name?}` → 复制成员 + 布局（新 id） |
| POST | `/orchestrate/start` | **新增可选 `workflowId`**；后端把成员/名称快照进 run |
| GET | `/orchestrate/runs` | **新增 `workflowId` / `workflowName`** |
| GET | `/orchestrate/run?id=` | **新增 `workflowId` / `workflowName`** |

校验（后端集中做，前端只做人话提示）：

- `name` 非空（默认「未命名工作流」）；成员 1~8；每个成员必须有 `engine`；
- `cwd` 不能是盘符根 / 系统目录（复用现有项目目录校验思路）；
- 非法 id（`../`）拒绝；删除不存在 → 404。

## 7. UI 设计

### 7.1 视图结构（工作台内两个视图）

```
#collab
├── 顶栏：协作 · [工作流] [运行] · 项目筛选 · ＋ 新建工作流 · 刷新 · ×
├── 左栏（共用）
│   └── 项目 → 工作流（可折叠）→ 最近运行（点击打开结果）
├── 主区（工作流视图）
│   ├── 工作流头：名字 / 项目 / 成员数 / 上次运行 / [▶ 运行] [编辑] [复制] [删除]
│   ├── ★快速任务条： [这次的补充要求/任务…]  [▶ 运行]   ← 不用弹窗
│   └── ★画布：#collab-canvas（SVG 连线层 + 节点层，可拖/缩放）
└── 主区（运行视图）
    └── 现有三列 / 待批 / 差异 / 仲裁（保持不变）
```

> 默认进入**工作流视图**；从运行历史点一条 run 才切到运行视图。
> 空状态：没有工作流时，显示 3 步引导（新建工作流 → 加成员 → ▶ 运行）。

### 7.2 画布（参考 LibTV 的节点画布观感）

```
┌────────────┐        ┌──────────────┐        ┌──────────────┐
│  任务节点   │───┬───▶│ 实现者 · impl │◀╌╌╌╌╌╌▶│ 审查者 · rev  │
│ 登录重构    │   │    │ codex-node    │ 评审    │ opencode-acp  │
│ [▶ 运行]    │   ├───▶│ 实现者 2      │        │ 结论：推荐 X  │
└────────────┘   │    └──────────────┘        └──────────────┘
                 └───▶│ 测试者 · test │◀╌╌╌╌╌╌▶│ 仲裁节点（可选）│
```

- **节点类型**
  - `task`：左侧，显示工作流名 + 默认任务 + ▶；
  - `member`：中间，卡片显示 角色小标 / 名字 / 引擎 / 最后一次状态（等待/运行/完成/失败）/ tokens；
  - `arb`：右侧，显示"审查者/仲裁"（若工作流里有 reviewer 角色；没有就不显示）。
- **连线**
  - `task → member`：实线（每个成员都会收到同一任务）；
  - `member ↔ arb`：虚线（审查者会看到所有成员输出；仲裁结果回到工作流）。
  - v1 **不可手画**（避免误解成执行依赖）；拖动节点时连线跟随。
- **交互**
  - 拖动节点改位置 → 松手保存 `layout`（防抖 500ms）；
  - 滚轮缩放（0.6~1.6）+ 空格/中键拖动画布；「适应窗口」按钮；
  - 双击节点 → 右侧检查器（角色/名字/引擎）；成员节点右上角 × 删除；
  - 画布空白处双击 / 顶部「＋ 成员」→ 新增成员（默认实现者）；
  - 节点状态用颜色 + 轻脉冲（运行中），**不阻塞拖动**。
- **自动布局**（首次打开 / 点「重新排布」）：
  - task 在左；成员按角色分组堆叠（implementer/tester 中列，reviewer 右列）；arb 最右；
  - 间距固定，避免重叠；用户拖过后以用户坐标为准。
- **点节点看结果**：运行中/结束后点节点 → 切到运行视图并滚到对应列（复用现有列/差异/仲裁）。

### 7.3 "不再每次新建任务"（核心便利性）

| 入口 | 行为 |
| --- | --- |
| 工作流头 / 快速任务条 | 输入本次任务（预填 `taskTemplate`）→ **▶ 运行**，直接创建 run（带 `workflowId`），不弹窗 |
| 运行页「再跑一次」 | 已有（`collabRerun`），补一个**内联输入**"改任务再跑" |
| 左栏工作流行 | 悬停出现 **▶**，用默认任务一键跑 |
| 新建任务的弹窗 | 改名 **「新建工作流」**（只需做一次）；只有"临时一次性任务"才从运行页发起 |

### 7.4 左栏（项目 → 工作流 → 运行）

```
D:\work\proj-a                 (项目)
  ▸ 登录重构        wf_... · 3 成员 · 上次 10:20  [▶]
      run_10:20  完成 3/3
      run_09:40  完成 2/3
  ▸ 接口联调        wf_... · 2 成员 · 上次 昨天
未归属运行（历史）
  run_...（0.2.9 之前）
```

- 现有「按项目筛选」保留（工作流多时仍可用）；
- 项目 / 工作流行可折叠；记住展开状态（localStorage，按项目路径）。

## 8. 分阶段施工计划（按这个顺序做，每阶段可独立交付）

### P0 · 先解决"每次都要新建"（0.5~1 天）

**目标**：不改数据模型，先让"重复使用"变顺。

1. 运行页增加「**改任务再跑**」：一行输入 + Enter → 用当前 run 的 `members/cwd` 直接 `start`。
2. 工作台顶部加「**快速开始**」条：用**最近一条 run** 的成员配置 + 一个任务输入 → ▶。
3. 新建任务弹窗保留（它是"第一次配置"的入口），文案改成「新建任务（一次性）」。
4. 无工作流数据、无后端改动。

**验收**：从一条已结束的 run，输入新任务 + Enter → 新 run 启动，成员/目录与原来一致；全程无弹窗。

### P1 · 工作流实体 + 左栏分层（1~2 天）✅ **已交付（`0.2.11`）**

1. 后端 `_collab_workflows.json` + CRUD + `start_run(workflowId)` + `list_runs` 带 `workflowId/Name`。
2. 前端「工作流」视图（列表/卡片，不做画布）：新建/编辑/复制/删除；每张卡「▶ 运行」+ 内联任务。
3. 左栏改成 项目 → 工作流 → 运行（保留项目筛选；旧 run 归"未归属"）。
4. 从运行页可「保存为工作流」（把当次成员存下来）。

**验收**：
- 建工作流 → 左栏出现在对应项目下 → 连跑两次 → 两条 run 都有 `workflowId`，历史归组；
- 改工作流成员不影响已完成的 run（快照）；
- 删除工作流不删 run（历史保留，显示工作流名快照）。

### P2 · 画布（2~3 天，主体）✅ **已交付（`0.2.11`）**

1. DOM：`#collab-wf-view`（头 + 快速任务条 + `#collab-canvas` + 检查器）。
2. 渲染：节点绝对定位 + SVG 连线层；`transform: translate/scale` 容器统一缩放。
3. 交互：拖动节点、保存布局（防抖）、缩放/平移/适应窗口、增删成员、双击检查器。
4. 自动布局 + 「重新排布」。
5. 运行态：`collabTick` 把成员状态映射到节点颜色（等待/运行/完成/失败）；**点节点看结果** ✅ 由检查器的「在运行结果里看 →」跳到最近一次运行并选中该成员（`0.2.18`）。
6. 连接线按角色推导（task→members；reviewer↔members）。

**验收**：
- 画布显示 1 个任务节点 + N 个成员节点 + 审查节点与连线；
- 拖动后刷新页面位置不变（落盘）；
- 画布上 ▶ 运行 → 生成带 `workflowId` 的 run，节点实时变色；
- 增删成员同步保存，成员 ≤8；
- 无新依赖、`jsbalance`/`check_ids` 通过。

### P3 · 收尾与迁移（1~2 天）✅ **已交付（`0.2.14`）**

1. 旧 run「另存为工作流」（按成员去重生成一个 wf）✅ —— `POST /orchestrate/workflows/from-run`，成员组合相同则复用。
2. 工作流复制 / 重命名 / 归档（归档不删除，收进折叠区）✅ —— 复制/改名/换目录在 `0.2.11`；归档 = `workflows/archive` + 左栏「已归档 N 个 ▸」。
3. 键盘：`Ctrl+Enter` 运行；`Esc` 关检查器；`Delete` 删选中节点 ✅。
4. 空状态三步引导 + 画布提示（第一次进来怎么用）✅ —— 三步卡 +「＋ 新建工作流」；画布左上角首用提示（只弹一次、不挡节点）。

### P4 · 阶段（串行 + 条件 + 重试）✅ **已交付（`0.2.15`）**

**方案与实施记录见 `docs/工作流阶段-方案.md`**。要点：

- **阶段串行、阶段内并行**：`stages[]`（最多 8 个）+ `members[].stage`；
- 后一阶段的 prompt 带**上一阶段产出**（每人 4000 字、总 12000 字封顶）；
- `when = always / onSuccess / onFailure`（看上一阶段）、`onFail = stop / continue`、`retries = 0~2`；
- 画布：任务 → 阶段节点（横排）→ 阶段内成员；拖阶段连带成员；阶段检查器；「＋ 阶段」/ `Delete`；
- 运行详情显示「阶段 x/y · 当前「名字」」，成员 chip 带阶段小标；
- 老工作流没有 `stages` → 自动归一成**一个默认阶段**（行为不变）。

**仍未做**：任意 DAG / 子工作流 / 富条件表达式 / 阶段级超时 / 与技能模板联动。

## 10. 验收标准（总）

1. **不用每次新建**：选一个工作流 → 输入任务 → Enter，3 秒内开跑；重复 3 次不需要打开弹窗。
2. **看得懂**：一条工作流在画布上能看到"任务 → 哪些成员 → 谁审查"；同一项目的多套工作流在左栏分得开。
3. **不破坏历史**：改工作流/删工作流后，旧 run 仍能打开、成员与结果不变。
4. **兼容**：没有工作流的旧 run 仍显示（归"未归属"）；不走 `/workflows` 的老前端不受影响。
5. **回归**：`orchestrator_test`、新画布测试、`check_features`（0 缺失）、`run_suite` 全绿；`jsbalance`/`check_ids` 通过。
6. **零新依赖**：不引入画布库 / 构建步骤。

## 11. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 画布被误解成"任意 DAG 执行" | 画布副标题明写「同一任务并行派给成员；连线由角色推导」；P4 才做串行 |
| 拖拽/缩放与面板缩放（`zoom`）冲突 | 画布坐标用设计像素；拖动换算 `uiZoom()`（项目已有先例） |
| 布局数据与成员 id 漂移 | 保存时按 id 校验；删除成员同时清坐标；加载时丢弃未知 id |
| 旧 run 没有 workflowId | 全部归"未归属"；提供"另存为工作流"，绝不自动猜 |
| 左栏树太长 | 项目/工作流折叠 + 记住展开；工作流按 `updated` 倒序 |
| 运行中画布频繁重绘 | 只在 `collabTick`（1.5s）里更新节点 class/text，不重画整块 DOM |
| 8 成员 + 长名字挤爆 | 节点固定宽 + 省略号 + title；自动布局按行堆叠 |

## 12. 建议开工顺序

1. **P0（半天）** —— 先把"每次新建"的痛点消掉，风险最低、用户立刻有感。
2. **P1（1~2 天）** —— 工作流实体与左栏分层，为画布打地基。
3. **P2（2~3 天）** —— 画布本体。
4. **P3** 收尾 + 迁移。

> P0 与 P1 可以合并成一次交付（`0.2.11`）；画布单独一个版本（`0.3.0` 或 `0.2.12`，按项目习惯用 patch 号）。

## 13. 节点级权限（`0.2.13` 补充）

| 项 | 说明 |
| --- | --- |
| 字段 | 成员多一个 `permLevel`：`""`（跟随面板）/ `ask` / `read` / `edit` / `exec` / **`trust`** |
| `trust` 语义 | **非破坏性操作自动放行**（读 / 写 / 执行 / 联网）；**破坏性仍然永远要人确认**，且放行前先进隔离区 |
| 保存位置 | 工作流 `members[].permLevel`（下次一键跑继承）→ 启动时快照进 run → 运行中 `POST /orchestrate/member {run, member, permLevel}` 也能改（只影响**下一条**申请） |
| UI | 画布检查器「权限」下拉（写回工作流）；运行详情「权限」抽屉里逐成员下拉（立即生效） |
| 为什么不是"全部放行" | Codex 不上报路径，旧规则 fail-closed 每条命令都问；`trust` 只放开"非破坏性"这一档，破坏性红线不动 |

⚠ 已挂起的申请不会因为改成 `trust` 而自动放行 —— 那一条仍然要你拍板（避免"改个设置就把队列清空"的误解）。
