# LICENSE 选项对比（cocraft）

> 目的：在**发布之前**把许可证定下来。现在仓库**没有任何 LICENSE**，按著作权法默认「保留所有权利」——
> 别人连 fork / 修改 / 再分发都不被允许，「开源」这句话在法律上是空的。
> ⚠ 本文是工程/商业权衡，不是法律意见；真要收费或进企业，发布前找律师看一遍。

---

## 0. 结论（先看这段）

| 方案 | 一句话 | 适合你现在的目标吗 |
| --- | --- | --- |
| **A. AGPL-3.0-only + 商业双许可**（推荐） | 社区真开源；企业不接受 AGPL 就买商业许可 | ✅ 最匹配「开源获客 + 团队版收费 + 防白嫖」 |
| **B. BSL 1.1（4 年后转 Apache-2.0）** | 源码可见，但禁止拿它做竞争性托管服务 | ✅ 次选，最防白嫖；但"不是 OSI 开源"，社区会挑刺 |
| **C. Apache-2.0（开源核心 + 专有团队功能）** | 最大采用度，靠团队功能收费 | ⚠ 别人可以 fork 出去开公司，你拦不住 |
| **D. 先私有（暂不加 LICENSE）** | 继续"保留所有权利" | ❌ 与"发 GitHub + 让人用"矛盾 |

**我的建议：A。** 你目前是**唯一版权人**（没有外部贡献），双许可在法律上最干净；
等以后接受外部 PR，再用 CLA 保住再许可权（见 §4）。

## 2. 三个候选的细节

### A. AGPL-3.0-only + 商业双许可

- **社区版**：AGPL-3.0，任何人可自用、可改；**若把修改版作为网络服务提供给别人**，必须提供源码（§13）。
- **商业版**：单独的商业许可（团队策略、审计导出、支持）。因为你持有全部版权，同一份代码可以用两套许可分发。
- **要点**：
  - 桌面本地使用不触发网络条款 → 普通用户无感；
  - 企业法务常直接禁 AGPL → 这正是"买商业许可"的动机；
  - 需要 `LICENSE`（AGPL 全文）+ `LICENSE-COMMERCIAL.md`（说明商业授权联系方式与范围）。
- **风险**：AGPL 会挡掉一部分"想在公司里用"的人；要接受这个筛选。

### B. BSL 1.1（Business Source License）

- 源码公开，**Additional Use Grant** 允许：个人使用、内部生产使用、评估、非商业研究；
- **限制**：不得提供与本产品竞争的托管/商业服务；
- **Change License**：Apache-2.0；**Change Date**：每个版本发布后 4 年（或统一一个未来日期）；
- **要点**：OSI 不认它是开源，README 里别写"open source"，写 **source-available**；
- **适合**：你最怕"别人直接拿去开公司"，且短期不指望社区贡献。

### C. Apache-2.0（开源核心 + 专有团队功能）

- 核心完全开源（含商业使用），团队功能单独闭源（`enterprise/` 目录或独立仓库）；
- 必须保留 NOTICE（若有），专利授权条款对用户友好；
- **风险**：竞品可以 fork 核心、自己加团队功能，你无法阻止；对单人项目，这是最容易被"白嫖"的路线。

## 4. 单人版权 → 以后接贡献的坑（重要）

- 现在是**你一个人**的版权 → 双许可 / 改许可都合法。
- **一旦合并了别人的 PR**，那份代码的版权归对方 → 你再想卖商业许可，必须拿到**再许可授权**。
- 落地建议（三选一）：
  1. **CLA**（Contributor License Agreement）：贡献者授予你再许可权（最稳，GitHub 上有现成模板）；
  2. **DCO + 明确声明**：`CONTRIBUTING.md` 写明"提交即同意以本项目许可（含商业再许可）分发"；
  3. 短期只接受 issue / 建议，不接受代码 PR（最省事，但社区长不起来）。

## 6. ⚠ 另一件会阻塞公开发布的事：素材版权

`frontend/assets/` 里的头像 / 背景 / 立绘 / 贴纸是**《龙族》上杉绘梨衣的同人图**（AGENTS 里写着"同人图仅自用"）。

- 自用（本机）没问题；
- **发 GitHub + 随安装包分发** = 从"个人欣赏"变成"公开传播 + 大规模复制"，风险性质不同；
- 三个选项：
  1. **换原创/委托**（最稳，也最能当品牌资产）；
  2. **抽象/几何占位**（最快，视觉降级，但可以先发布）；
  3. **发布版剥离**：个人构建保留、公开发布版用占位（构建时开关）。

**建议**：发布前至少替换 `avatar.png` / `badge.jpg` / `hero.jpg` / `hiru-bg.jpg` / `night.jpg` / 两张 sticker。
这条不解决，前面所有"发布"动作都带着一个可被投诉的尾巴。
