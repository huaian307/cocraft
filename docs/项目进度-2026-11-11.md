## 3. 这一版的内容（`0.2.123`）

### 3.1 主题只剩「圣烛教堂」

- `:root` 直接就是 chapel 调色板（暖黑 `#17120f` / 米白 `#f6efe3` / 烛金 `#e0a24a` / 绣线金 `#d9bd83`）
  → 首屏不闪白；用户主题（`data-theme-user` 叠加）的底盘也跟着变
- 删掉全部 `[data-theme="hiru"]` 规则（纸白毛玻璃兜底 / 白纱隐藏 / 白字暗底那套）、
  设置里的第二张主题卡、`#theme-hint` 提示条、`backend/themes.py` 的 `BUILTIN` 条目
- 老浏览器 `localStorage["cocraft.theme"] === "hiru"` → 自动归一成 `chapel`（不弹提示）
- ⚠ `hiru-bg.jpg` **不是**浅色主题的素材：它就是 chapel 那张官方壁纸，别删

| JS | `40-music.js` → **同名空实现桩**；`41-visual` 的 `initMusicAudio`/`restoreMusicState` 加守卫；`11-engine` 设置绑定 → `__liteOn()` |

### 3.3 三个真 bug（都已复现并修掉）

1. **安装包"文件已损坏"** —— ISCC 编译被 120s 超时中途杀掉，只剩 52 MB 半截 exe（payload 826 MB）
   → 安装报 `The setup files are corrupted`。**别给 ISCC 设短超时**，正常包约 200 MB。
2. **删 JS ≠ 删功能** —— 只删 `40-music.js` 会让 44 处调用变 `syncLyricsVisibility is not defined`
   → 必须留同名空实现桩。
3. **跨 script 重复 `const`** —— 桩里写了 `const MUS`（它本在 `41-visual.js`，顶层 `const` 共享）
   → 整个 `41-visual.js` SyntaxError，表现成 `initWallpaperPicker is not defined`。
   自查：把 index.html 的 script 按序拼成一个文件，用随包 node `--check`。

顺带修的：`build.py` 缺 `import time`（`drop_tree` 重试路径 `NameError`）、`cleanup.py` 解码噪声、
`isolation.py` 的 `git apply -` 没把补丁喂给 stdin、`planner.py` 角色名 `implement` → `implementer`。

## 4. 「以后都不打包音乐」的落地

`packaging/build.py`：

- `--components` 默认 `terminal,panel`（不再含 `music`）
- 新增 `--with-music`（显式要音乐才带，且跳过 strip）
- 写了 `--components music,...` 也会被摘掉并提示
- `clean_payload()` 之后**自动**执行 `packaging/strip_music.py`；**失败直接中止打包**
- `--check-lock` 不再把 music 的 venv 算缺失


## 6. 关键决策

1. **音乐从"必选组件"降级为"默认不带"**：用户明确"以后都不打包音乐"，所以做进构建默认，
   而不是每次手工跑 `strip_music.py`（手工步骤迟早会被忘）。
2. **源码保留音乐功能**，只在打包时摘除：dev 环境仍可自测；真要长期不维护再改源码级开关。
3. **旧发布只删附件、不删 Release**：历史说明（版本内容、日期）仍可查，但下载只有一个最新包。
4. **不移动 tag**：`cf680b7` 只是打包工具改动，产物字节不变，重发 Release 没有意义。

## 7. 风险与边界

1. 安装包**未签名** → SmartScreen 会提示；LICENSE / SBOM / 依赖审计仍未落地。
2. 精简包是**构建期摘除**：`check_features` 里音乐相关断言仍按源码算，CI 验证的是"源码态"。
3. 社区主题按「底盘 + 叠加」编写，删掉浅色底盘后，**浅色系社区主题**需要自己在 `theme.css` 里给全变量。
4. 本地接口无鉴权；审计链整条被高权限删除查不出（已知边界）。
