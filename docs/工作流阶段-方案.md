# 本地协作工作台 · 阶段（P4）方案与实施记录

> 状态：**已交付（`ui 0.2.15`）** · 2026-10-22
> 关联：`docs/工作流画布-方案.md`（P1/P2/P3）、`backend/orchestrator.py`、`frontend/app.js`（`COLLAB`）
> 前置事实：P1~P3 的执行模型是**扇出**（一个任务同时派给 N 个成员）。P4 把它升级为
> **阶段串行 + 阶段内并行**，但**仍然不是任意 DAG**（不手画依赖、不做子工作流）。

---

## 1. 要解决什么

之前一条工作流的所有成员**同时**开工：
- 审查者拿不到实现者的产出，只能「一起盲审」；
- 也没法表达「先实现 → 再审查 → 最后测试」这种最常见的串行打法；
- 某一阶段失败时，没法自动停或继续，更不能只重跑失败的人。

P4 的目标：**让一条工作流分几段先后做，后一段能看到前一段的产出，并能配置失败策略与重试。**

## 2. 数据模型

工作流（`runtime/state/_collab_workflows.json`）：

```jsonc
{
  "id": "wf_...",
  "name": "登录重构",
  "stages": [
    { "id": "s1", "name": "实现", "when": "always",    "onFail": "stop",     "retries": 0 },
    { "id": "s2", "name": "审查", "when": "onSuccess", "onFail": "continue", "retries": 1 }
  ],
  "members": [
    { "id": "m1", "role": "implementer", "name": "impl", "engine": "codex-node", "stage": "s1" },
    { "id": "m2", "role": "reviewer",    "name": "rev",  "engine": "opencode-acp", "stage": "s2" }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `stages[]` | 顺序就是执行顺序；**最多 8 个** |
| `when` | `always`（默认）/ `onSuccess`（上一阶段无失败才跑）/ `onFailure`（上一阶段有失败才跑）；**第 1 阶段忽略** |
| `onFail` | `stop`（默认，后续阶段 skipped）/ `continue`（继续跑） |
| `retries` | 0~2；阶段内**失败的成员**重跑（每次新会话） |
| `members[].stage` | 属于哪个阶段；认不出 / 缺失 → 第一个阶段 |

**兼容**：老工作流没有 `stages` → 运行时归一成**一个默认阶段**（等于原来的扇出），不改老行为。
阶段 id 统一重排为 `s1..sN`；成员 id 仍是 `m1..mN`。

运行（`runtime/state/_orchestrator/runs/<id>.json`）新增阶段快照：

```jsonc
{
  "stages": [
    { "id": "s1", "name": "实现", "when": "always", "onFail": "stop", "retries": 0,
      "status": "done", "started": 1792658000000, "ended": 1792658010000, "note": "" }
  ],
  "members": [ { "id": "m1", "stage": "s1", "retryCount": 0, "status": "done" } ]
}
```

阶段状态：`wait` / `running` / `done` / `partial` / `failed` / `skipped` / `cancelled`。
成员状态新增 `skipped`（条件不满足 / 前面失败 / 取消）。

## 3. 执行语义（`backend/orchestrator.py`）

```
任务
 └─ 阶段 1（成员并行，各自的 role 提示词）
      └─ 全部终态 → 有失败且 retries>0 → 失败的成员重跑
 └─ 阶段 2：when 检查上一阶段 → 拼提示词（上一阶段产出 + 本次任务 + 阶段身份）→ 并行
 └─ ...
```

关键点：

1. **阶段边界 = 等上一阶段所有成员终态（含重试）**；
2. **上一阶段产出**由 `_stage_digest()` 汇总成 Markdown（每人 4000 字、总 12000 字封顶），
   经 `_stage_body()` 拼进下一阶段每个成员的 prompt —— 审查者因此看得到实现者的原文；
3. **`onFail=stop`**：阶段失败后，后面所有阶段直接 `skipped`（成员也 skipped，不启动进程）；
4. **`when`**：`onSuccess` 在上一阶段有失败时跳过；`onFailure` 在上一阶段全部成功时跳过；
   **被跳过的阶段不计入失败**，run 仍然可以是 `done`；
5. **重试**：只重跑**失败的成员**（每次新建会话，`retryCount` 累加），成功的成员不重跑；
6. **取消**：`cancel_run` 置 cancelled → 阶段调度在边界检查，后面阶段不再启动；
   正在跑的成员由 `_run_member` 收成 `cancelled`，没启动的收成 `skipped`；
7. **不提前收口**：`_update_run()` 只有在**所有阶段都终态**时才把 run 置为
   done/partial/failed（以前「成员全终态」就够了 —— 分阶段后那样会让 run 在阶段 2 还没开始时显示完成）；
8. **删除不复活**：删除运行记录后，还在收尾的线程再 `_save()` 会被 `_deleted` 标记挡住
   （否则会把删掉的文件写回来）。

## 4. API

| 方法 | 路径 | 变化 |
| --- | --- | --- |
| POST | `/orchestrate/workflows/save` | **新增可选 `stages[]`**；返回归一后的 `stages` + `members[].stage` |
| GET | `/orchestrate/workflows` | 返回里带 `stages`（老数据补默认阶段，只读归一） |
| POST | `/orchestrate/start` | 不变；带 `workflowId` 时用工作流的 `stages` |
| GET | `/orchestrate/run?id=` | **新增 `stages`** 快照；成员多 `stage` / `retryCount` |
| POST | `/orchestrate/workflows/from-run` | 另存为工作流时**一并保存 run 的阶段快照** |

## 5. 画布与界面

- **节点**：任务节点 → **阶段节点（横排）** → 阶段内成员（竖排）。阶段节点显示
  「阶段 N / 名字 / 几个成员 · 条件 · 失败策略 · 重试 / 当前状态」。
- **连线**：任务 → 阶段 1；阶段 i → 阶段 i+1（**串行主链**）；阶段 → 它的成员（扇出）。
  旧的「reviewer 虚线」删掉 —— 串行阶段已经表达了评审关系。
- **拖阶段** = 连它下面的成员一起拖；拖成员只动它自己。
- **检查器**：
  - 点阶段 → 名字 / 条件（第 1 阶段禁用）/ 失败策略 / 重试；
  - 点成员 → **阶段** / 角色 / 名字 / 大脑 / 权限；
  - 改完自动保存（和 P3 的布局/权限同一条链路）。
- **加/删**：头部「＋ 阶段」；阶段节点 × / `Delete` 删除（成员自动移到相邻阶段，至少留一个阶段）。
  「＋ 成员」挂到当前选中的阶段，否则最后一个。
- **运行详情**：任务头显示「阶段 x/y · 当前「名字」」；成员 chip 与列头带阶段小标。
- **新建工作流**默认两阶段：**实现（s1）→ 审查（s2）**。
- **默认排布**：阶段在左、成员在右侧竖排（一行一个阶段）；「分阶段」按角色把审查者拆到阶段 2（旧单阶段工作流会高亮提示）。
- **`0.2.16` 起**：工作台是**整窗**（`fixed`，盖住侧栏 / 顶栏 / 播放条，只给底部输入区让位）；
  画布上方那条任务输入**整条搬到「小本子」的位置**（底部 = 标签 + 任务输入 + **▶ 运行**），
  关闭工作台时搬回、聊天输入恢复；工作台里按 Enter / 点「▶ 运行」都走工作流，**不会发聊天**。

## 6. 明确没做（避免误解）

- ❌ 任意 DAG（手画依赖、并行分支汇合）—— 只有**线性阶段**；
- ❌ 子工作流 / 阶段引用另一个工作流；
- ❌ 富条件表达式（只认上一阶段成功/失败两种）；
- ❌ 阶段级超时（仍是每个成员 `RUN_TIMEOUT`）；
- ❌ 与「技能 / 模板」联动（工作流工坊的事）。

## 8. 踩坑记录

- **`list_runs` 的 `members` 是数字**（摘要把成员数放在同名字段里）。画布早期把
  `collabWfLastRun()` 的摘要当成完整 run 用 → `(run.members || []).forEach is not a function`。
  现在画布只吃**当前打开的完整 run**（`collabWfRun`），摘要只用于「上次状态」文字。
- **不能让 `_update_run` 按「成员全终态」收口**：分阶段时后续成员还是 `wait`，本来不会触发；
  但**最后一段**的成员一完成就会提前把 run 置 done/partial，而阶段状态还在更新 —— 必须等阶段也终态。
- **删除运行记录 vs 收尾线程**：阶段调度线程不属于 `_ACTIVE`，删除后它仍可能 `_save`，把文件写回来。
  用 `run["_deleted"]` 在 `_save` 里挡住。
