## 3. 能力现状（这次真正变了的）

### 3.1 ACP 与 OpenCode 对齐

- **上下文压缩**：共享库里的 `compaction` 行不再被丢弃；非 opencode agent 的 `compaction_summary_chunk` 单独成一条 `compaction` 消息（面板「会话已压缩 + 可折叠摘要」）；
- **费用**：`usage_update.cost` 不再被丢弃（累计 / 逐轮增量自适应）；opencode-acp 按共享库逐条 `cost` 求和写回会话；
- **内置技能**：ACP 技能清单并入 OpenCode 的 `/builtin`（问本机服务、5 分钟缓存、磁盘同名覆盖）；
- **技能 resume**：不再把技能全文当用户消息发出去（留 `skill` 消息 + 正文走 `pendingSkills`）；
- **模型元数据**：`capabilities` 用 agent 真宣告；价格可选 `runtime/state/_model_prices.json`（没配就 null）。

### 3.2 会话删除语义

- 删除本地会话：**先 `session/delete`**（真删），失败才 `session/close`（只关闭）；
- 面板回 `agentSide`，只 close 时明确提示「它还会出现在接续里」；
- 「接续」列表新增 ×：**不先接续也能删 agent 侧会话**；
- 实测 codex-node 支持 `session/delete`（错 id 回 `-32603`，不是 `-32601`）。

### 3.3 新建项目目录策略

| 场景 | 落点 |
| --- | --- |
| agent 有自己的客户端目录（codex / claude / opencode） | `<CODEX_HOME 或 ~/.codex>/projects`、`~/.claude/projects`、`~/.local/share/opencode/projects` |
| 没有（dsh / 面板内 npm 装的） | `cocraft/runtime/projects/<agent-id>` |
| 工作流 | `cocraft/runtime/workflow-projects/<项目名>`（所有成员共用） |
| 覆盖 | `runtime/state/_project_roots.json`（`agents` > `cocraft` / `workflow`） |

> 随包 agent 的 `CODEX_HOME` / `XDG_DATA_HOME` 本来就在 cocraft 目录下 → 自动归到 cocraft，符合"没有自己的桌面端就放 cocraft"。

## 5. 风险与边界

1. **未打包 / 未签名 / LICENSE 未落地**：线上仍是 `v0.2.62`，本轮改动未进安装包；
2. **本地接口无鉴权**：有 shell 的 agent 理论上能改运行态；审计链能查"改过"，查不出"整条被删"；
3. **轮快照默认只记文件名**（`with_content=False`）→ 不能回滚内容，要开「轮快照带内容」；
4. **工作流无 worktree 隔离**：多个成员共用一个目录，会互相看到/覆盖（有每轮快照与审计兜底）；
5. **团队版没有集中管控**：审计在每台机器本地，聚合靠导出；
6. **客户 PoC 的门槛**：安装包未签名 → 杀软/域环境下可能被拦，必须先在一台试点机验证。
