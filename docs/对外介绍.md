# cocraft

### 敢让 AI 动你电脑的多智能体协作台

> **本地运行 · 多厂商 agent 同台 · 5 分钟搭一套流程 · 每一步可撤回 · 每次动刀都要你点头**

`Windows x64` · `内测中` · 当前开发版 `0.2.61`（线上可下载 `0.2.13`）
**官网**：<https://cocraft.cc.cd>
**下载**：<https://github.com/huaian307/cocraft/releases/latest>

---

## 30 秒看懂

cocraft 是一个跑在你自己电脑上的 AI 协作台。

你可以同时开几个 agent（Claude Code / Codex / OpenCode / 其它支持 ACP 的 agent）干不同的活，
而它只负责五件事：

- **动手之前，先留底**
- **破坏性操作，先隔离**
- **每一步权限，你点头**
- **出了事，一键退回**
- **每一步都有据可查**：append-only 审计链，可离线校验、可签名导出

它不训练模型、不上传你的代码、不要求注册账号。
你用自己的 API Key 或本机已登录的客户端，代码只在你配置的模型调用时才离开本机。

## 为什么需要它：三个真实瞬间

**① “它把我 `dist` 目录删了。”**
git 里没有未提交的内容，回收站里也找不到。你只能重来。

**② “我不知道它刚才到底跑了什么。”**
它说“完成了”，但中间执行了哪 37 条命令、改了哪些文件、有没有联网，你无从查证。

**③ “三个 agent 同时改一个仓库，谁改的？”**
并行很爽，但冲突、覆盖、责任归属，全靠你自己盯。

**④ “公司不让把代码传到云上。”**
云端 agent 很好用，但你的代码不能出内网，账号也不能注册。

cocraft 就是为这四个瞬间做的。

## 四个核心能力

### 1. 可撤回：AI 动过的，能退回去

- **破坏性操作先隔离**：命中删除 / 格式化 / 关机等命令时，**先把目标复制进隔离区**，再等你确认放行；
- **每一轮留快照**：工作区做内容寻址快照（增量写、天然去重），随时能看“这一轮改了什么”；
- **行级 diff**：改 / 增 / 删 / 改名四类，点开看红绿逐行差异；
- **一键退回**：被删的恢复、被改的回滚、新增的删掉；撤销“新增”前还会先自动隔离 —— **撤销本身也可逆**；
- **诚实**：识别不出目标、隔离失败、恢复冲突，都会明确告诉你，**不假装成功**。

> ⚠ 它是**尽力而为的安全网，不是数据库事务**。能识别的目标才保得住；保不住的会如实说。

### 2. 权限护栏：不是“全放行”，也不是“每步都烦你”

- **5 档权限**：全部询问 / 只读 / 读写 / 执行 / 信任；
- **范围未知一律问**（fail-closed）：agent 不报路径时，不会默认当成“工作区内”；
- **破坏性操作永不自动放行**：等级再宽也要你确认，而且只认“确认”；
- **节点级信任**：某个成员可以设“非破坏性自动放行”，删除 / 格式化这类仍然拦住；
- **逐条审批卡片**：命令原文、涉及路径、倒计时；处理完留审批记录。

### 3. 多 agent 工作台：看得见、比得了、追得回

- **并行派活**：一条任务同时给多个成员，各自独立进程 / 会话；
- **并排对比**：每人一列，Markdown 渲染；正好两人时给逐行差异；
- **结果仲裁**：请审查者给结论，抠到“推荐 X”可一键跳到那一列；
- **工作流画布**：把“成员 / 角色 / 目录 / 默认任务”存成可复用工作流；
- **阶段串行**：实现 → 审查 → 测试，后一阶段能看到前一阶段的产出；
- **条件 / 失败策略 / 重试**：按上一阶段结果决定是否继续；
- **运行历史**：项目 → 工作流 → 运行，可筛选、可归档、可另存为工作流。

### 4. 可审计：谁批准的、跑了什么、留下了什么

- **审批时间线**：谁批的 / 拒绝的、**命令原文**、路径、时间；
- **审计链**：append-only JSONL + **哈希链**（每条带 `seq` / `prev` / `hash`）—— 改掉任何一条，链就断了；
- **能离线复核**：独立脚本校验导出（JSON / CSV / 原始 `.jsonl`，连归档一起算）；
- **能签名**：复用系统 OpenSSH 的 `ssh-keygen -Y sign`，核对「这份是谁给的、之后有没有被改」；
- **能归档**：主文件超 4 MB 自动把最旧一段搬进归档目录，归档动作本身也入链（跨文件仍是一条链）；
- **一页报告**：结论分布 / 破坏性操作逐条 / 明细，导出 Markdown；
- **区分「人点的」和「程序调的」**：每条记录带 `via = ui / api / system`；
- **AI 成员改了什么**：每轮派活收尾记文件级改动（只记文件名 + 增删改计数，不存内容）。

## 5 分钟搭一套流程（画布搭一次，之后一键复跑）

工作流是**可复用实体**：成员、角色、默认任务、项目目录、画布布局、阶段都存下来，跑过的还能直接存成工作流。

| 你看到的 | 你做的事 |
| --- | --- |
| 画布：任务 → 阶段（横排）→ 阶段内成员 | 拖几个成员进去 |
| 角色：实现者 / 审查者 / 测试者 / 调研者…（群聊里还有「一键建组」的 3 套内置组合） | 选角色，或从一次真实运行「存为工作流」 |
| 默认权限：实现可写、审查只读；删除 / 格式化仍然要你确认 | 一眼看懂 |
| 阶段可设「条件 / 失败策略 / 重试」，后一阶段能看到前一阶段的产出 | 需要才配 |
| 选目录 + 写任务 | 点运行（Ctrl+Enter） |

跑完还可以：

- **把这次真实运行存成工作流**（成员按「目录 + 组合」去重），下次一键复跑；
- **归档**旧工作流（不删，收进折叠区）；
- **导出运行记录 / 审计**（JSON / CSV / Markdown）交给同事或客户。

> 📋 规划中：**模板库 + 4 步向导**（选模板 → 选目录 → 填任务 → 跑）和工作流一键分享（团队版）。
> 现在要"开箱即用"，最近的路径是**群聊 ☰ 菜单里的「一键建组」**（三套内置组合：开发 + 审查 + 测试 / 实现 + 审查（对拍）/ 调研 + 审查）。

> 为什么这算差异：Claude Code 的 agent teams 要先在 `settings.json` 开实验开关，Codex 要改 `config.toml` 再进 `/experimental`，Cursor 的后台 agent 也没有「实现 → 审查 → 测试」的可复用流程 —— 官方都在优化"建一个 agent"，还没人把"搭一套流程"做成一键。

## 和你已经在用的工具，是什么关系

cocraft **不替代**它们，它补的是“操作层的护栏”。

| 你已经在用 | 它不管的地方 | cocraft 补什么 |
| --- | --- | --- |
| **Claude Code** | `/rewind` 是会话级检查点，官方文档写明**不覆盖 shell 命令造成的改动、不覆盖子 agent 的编辑** | 整工作区快照 + 破坏性命令隔离 + 行级回退 |
| **Codex** | 截至 2026-10，**没有 rewind / revert** | 统一的可撤回能力（跨 agent） |
| **Cursor / 其它 IDE agent** | 偏编辑器内体验；改动回滚靠 git | 本地文件级快照 + 审批 + 审计 |
| **Conductor / Vibe Kanban / Claude Squad** | 主要是 macOS/Linux 的并行工作台，靠 git worktree | **Windows 原生** + 不依赖 git（普通文件夹也能撤） |
| **云端 agent（Codex 云端 / Devin 等）** | 代码要上去，账号要注册 | 本机运行、自带 Key、数据不出机 |
| **官方多 agent 流程（Claude agent teams / Codex subagents）** | 要改配置文件 / 开实验开关 / 自己拼阶段，没有模板与分享 | 画布 + 阶段 + 条件/重试，跨厂商同一套（模板库与向导在规划中） |
| **git** | 只管已提交的内容 | 管“这一步到底动了什么”，包括未提交与命令副作用 |

> 竞品能力截至 2026-10 的公开文档；上游迭代很快，以各自官方说明为准。

## 5 分钟上手

1. **下载安装**：Windows x64 安装包（内测版未签名，SmartScreen 可能提示，选择“仍要运行”）。
2. **首次启动**：一个向导页填完 —— 对话引擎 /（ACP）agent / 模型 Key / 默认模型，点「完成并重启」。
3. **想换 Key / 加账号**：设置 → 模型凭据（支持同一家**多个账号**并存、每个 agent 选一个；界面只显示掩码，明文只在本机）。
4. **建一个工作流**：给一个目录、加两个成员（实现 + 审查）、写一句任务。
5. **跑**：点运行（Ctrl+Enter）；遇到权限申请就批准；跑完看结果列、差异、撤销。

**30 秒演示脚本**：
> 三个 agent 领任务 → 其中一个要跑命令（弹权限卡片）→ 一条破坏性命令进隔离区 → 点“撤销这一轮” → 文件回来了。

## 适合谁

- **外包 / 工作室**：多项目、多客户，要给甲方交代“AI 改了什么、谁批的”；
- **独立开发者接商单**：一次事故就赔钱，需要兜底；
- **3~15 人小团队**：想用 AI 提效，但不敢让它无约束地动生产目录；
- **数据敏感场景**：代码不能上云，只能用自带 Key 的本地工具；
- **同时用多家 agent 的人**：Claude / Codex / OpenCode 混用，权限模型各不相同。

## 不适合谁

- 只想要“最强模型写代码”的人（直接用官方 CLI 更省事）；
- 完全在云端协作、不需要本地文件的团队；
- 期待“全自动、不需要人看”的人 —— 这个产品的核心恰恰是“重要的事要你点头”。

---

## 它不是什么（避免误会）

- ❌ 不是模型，也不是 Agent 框架 —— 它管的是“agent 怎么在你电脑上动手”；
- ❌ 不是云 IDE / 云沙箱 —— 一切在本机；
- ❌ 不是 git 的替代品 —— 它管会话级的“这一步改了什么”，长期版本仍交给 git；
- ❌ 不是企业合规套件 —— 没有 SOC2 / SSO / 集中管控（这些是团队版规划的方向）。

## 常见问题

**Q：它会不会把我的文件删了？**
A：它会**先隔离再放行**，并且破坏性操作永远要你确认。但它是尽力而为的安全网：识别不出目标、目标太大、权限外的情况，会明确告诉你“这次没能保住”。**重要目录仍建议配合 git 和备份。**

**Q：需要联网吗？**
A：cocraft 自己不上传任何东西；但 agent 调用模型需要网络。用本地模型或内网网关也可以配。

**Q：要不要注册账号？**
A：不要。没有账号体系，没有云端存储。

**Q：能保存多个 API Key 吗？**
A：可以。同一家多个账号（个人 / 公司）也能共存，每个 agent 可以选「用哪个凭据」；界面上只显示掩码，明文只在本机。

**Q：怎么证明“记录没被改过”？**
A：审计链是 append-only + 哈希链，改掉任何一条都会**断链**（面板直接显示「第 N 条断裂」+ 原因）；导出后还能用独立脚本**离线复核**（JSON / CSV / 原始日志，连归档一起算），需要的话再用系统 OpenSSH 做**签名导出**，核对“这份是谁给的、之后有没有被改”。

**Q：怎么更新？**
A：设置 → 软件更新 → 检查更新 → 一键更新（下载完静默安装，装完面板自动重启）。万一这台机器起不了 PowerShell，会改为直接启动已下载好的安装包，装完自己重开面板即可；设置不会被覆盖。

**Q：支持哪些 agent？**
A：OpenCode，以及任何支持 ACP 的 agent（Codex、Claude Code、OpenCode 自带 ACP、dsh 等）。可在面板里扫描本机或直接 npm 安装。

**Q：收费吗？**
A：**个人使用免费，并包含全部安全能力**（撤销 / 隔离 / 权限 / 本地审计）。
团队版（多成员汇总、集中策略、签名审计、支持）在规划中，细节尚未定价。

**Q：开源吗？**
A：核心计划开源（许可证待最终确定）。团队版功能会单独授权。发布前会补 `LICENSE` 与第三方许可说明。

**Q：为什么只有 Windows？**
A：先把一个平台做透。macOS/Linux 上已有不少免费竞品，而 Windows 本地护栏这块基本空着。

**Q：安装包为什么没签名？**
A：证书暂时拿不到；当前用 SHA256 校验 + 明确说明代替。介意的话可以自行从源码构建。
