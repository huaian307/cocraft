# cocraft

### 你的 AI Agent，你的规则

> **Local Agent Control Plane** · 面向 AI 编程时代的**本地 Agent 操作控制台**
> 不管你用 Claude Code、Codex、OpenCode 还是别的 ACP agent —— 它负责三件事：
> **能做什么 · 实际做了什么 · 出了问题怎么恢复**
> **默认全程本地；团队版只同步端到端密文（密钥在你手里）。**

`Windows x64` · `内测中` · 当前开发版 `0.2.111`（线上可下载 `0.2.62`）
**官网**：<https://cocraft.cc.cd> · **下载**：<https://github.com/huaian307/cocraft/releases/latest>

---

## 30 秒看懂

cocraft 不训练模型、不做代码补全、不替代你的 IDE。

它管的是**另一层**：AI agent 在你电脑上**动手**时的边界。

```
Before Action     操作前：危险动作先隔离、先问你
Under Control     过程中：跨厂商同一套权限，谁能做什么由你定
Full Traceability 事后：每一步谁批的、改了什么、能不能退，都有据可查
Recoverable       出事时：被删的能恢复、被改的能回滚（在能力范围内）
```

它不注册账号。**默认全程本地**：代码与文件不上传，只有你配置的模型调用本身会联网。
开启团队版后，同步出去的只有**端到端加密的审计包** —— 密钥在你们手里，**我们看不到明文**。

## 数据边界：默认不出机，团队版只出密文

| 模式 | 什么会离开本机 | 谁能看到明文 |
| --- | --- | --- |
| **本地模式（默认）** | 只有你配置的模型调用 | 本机（模型厂商按其条款） |
| **团队 · 共享目录** | 签名 + 加密的审计包（放你们自己的 NAS / 网盘） | 只有装了团队密钥的成员 |
| **团队 · 中继（可选）** | **密文** + 最少路由元数据 | **只有你们** —— 我们和运维都看不到 |
| 企业自建 | 同共享目录 / 中继，走你们内网 | 你们 |

**中继能看到**：密文大小、上传时间、不透明团队/机器 ID、包序号。
**看不到**：审计正文、命令原文、文件路径、文件名、成员姓名。

> 诚实边界：加密保护的是**传输与存储**；**被攻陷的终端**仍然可以撒谎或泄露明文。另外，被移除的成员**解不开之后的包**，但已经下载到本地的旧包仍能解开 —— 无法远程擦除。

## 先看一个真实场景

你让 Codex：「重构项目，清理无用文件，并重新构建。」

它可能做了这些事：

- 改了 12 个源码文件；
- 删了 3 个文件（其中一个**没提交过**）；
- 执行了 `npm install`；
- 执行了 `rm -rf dist`；
- 改了一个本地配置；
- 发起了几次联网请求。

**Git 能帮你看清、比较、恢复仓库里的文件变化** —— 但它不负责：

- 在执行危险命令**之前**拦一下；
- 让你按**具体这一条命令**审批；
- 记录**是谁、什么时候**批准的；
- 在删除前把目标**先复制**下来；
- 把多次 agent 操作和各自的结果**关联**起来；
- 给不同的 agent 设**不同权限**。

这正是 cocraft 要补的那一层。

## 它到底控制什么

### 一套策略，管住所有接进来的 agent

| 操作 | 建议策略（可调） |
| --- | --- |
| 读取项目内文件 | 自动允许 |
| 修改源码 | 自动允许 |
| 安装 npm 包 / 执行命令 | 询问 |
| 删除文件 | **必须审批**（删除前先隔离） |
| 删除整个目录 | **隔离后审批** |
| 访问项目外目录 | 询问 |
| 读取敏感文件（环境变量 / 凭据 / 密钥） | **拒绝**（即使等级很宽也要问） |
| 关机 / 杀进程 / 格式化 / 注册表删除 | **永不自动放行**（没有可恢复的"原件"） |

权限等级 5 档：`全部询问 / 只读 / 读写 / 执行 / 信任`；工作流成员另有 `trust`（非破坏性自动、破坏性仍要确认）。
群聊成员的生效等级 = **min(面板等级, 成员上限)** —— 只紧不松。

### 事前预防，而不是事后懊悔

```
agent 准备执行 → cocraft 判断风险 → 隔离 / 审批 → 放行 → 记录 → 需要时恢复
```

不是"改坏了再想办法"，而是**动手前先把能保的保住**。

### 覆盖边界（必须说清）

cocraft 能管住的是**经过它接管的路径**：

- ✅ 通过面板接入的 ACP agent（codex / claude / opencode / dsh…）的 **shell 命令**与文件编辑；
- ✅ 面板内置的终端、文件查看的写入；
- ✅ 桌面 / 网页工具（`cu`）的动作；
- ⚠️ agent **自己开的新进程**、绕过 agent 直接调用的外部程序、**已经发出的网络请求 / 云端 API / 数据库写入 / 部署** —— 这些**不在**文件级保护范围内（见文末「它不是什么」）。

> 我们在持续验证 PowerShell / CMD / 子进程 / 脚本间接调用这些执行通道的覆盖率；**没覆盖到的会说出来**，不会假装全都拦得住。

## 三个核心差异

### 1. 跨 agent 的统一安全层

你家电脑上可能同时装着 Claude Code、Codex、OpenCode、Gemini CLI……
每家的权限机制、审批方式、恢复能力都不一样。**你不该为了管住它们，学五套安全配置。**

cocraft 把它们收进同一套规则：**同一份权限等级、同一套危险命令判定、同一条审计链、同一个恢复入口**。
你买到的不是"一个多 agent 界面"，而是**一套跨厂商的 AI 操作治理**。

### 2. 事前预防，不是事后恢复

| 常见做法 | cocraft |
| --- | --- |
| AI 改了文件 → 你发现错了 → 撤销 | AI 要动手 → 先判风险 → 先隔离 / 先问你 → 再放行 |
| 只覆盖"编辑器内的文件修改" | 覆盖 **shell 删除**、**未提交/未跟踪文件**、**普通文件夹**（不需要 git）、**桌面操作**（cu） |
| 恢复本身常常不可逆 | **回滚前再把当前文件备份一次** —— 撤回本身也可逆 |

### 3. 把 AI 开发过程变成可交付的材料

一次任务结束后，你能导出：

- **操作审批时间线**：谁批的 / 拒绝了、命令原文、路径、时间；
- **审计链导出**：原始 JSONL、34 列取证 CSV、9 列人话 CSV、一页 Markdown 简报；
- **离线复核**：独立脚本校验（JSON / CSV / 原始日志，含归档）；需要时用系统 OpenSSH **签名导出**；
- **每轮文件改动**：文件名 + 增/删/改计数（**不存内容**）；
- **工作流运行记录**：成员、阶段、仲裁结论、权限处理。

外包 / 工作室可以把它作为**交付附件**：这次用了哪些 agent、改了哪些文件、执行过哪些危险命令、哪些操作经过人工批准。

> ⚠ 边界：哈希链能**检出**记录被改动，签名能证明"这份导出是谁签的、之后有没有变"；
> 它们**不等于**"所有外部操作都被完整捕获"，也**不能**替代代码审查。

## 和 Git 是什么关系

**Git 管代码的历史，cocraft 管 agent 的操作。两层，互补。**

| 能力 | Git | cocraft |
| --- | --- | --- |
| 长期版本 / 分支 / 合并 / 远端协作 | ✅ 本职 | ❌ 不做（交给 git） |
| 查看与恢复**未提交**改动 | ✅ 支持（工作区 / 暂存区） | ✅ 也支持，但走的是**操作前隔离 + 轮快照**，不需要先提交 |
| **普通文件夹**（不是仓库） | ❌ | ✅ 设计目标之一 |
| **删除前先复制原件** | ❌ 不负责 | ✅ 核心能力 |
| **命令执行审批 / 危险动作拦截** | ❌ 不负责 | ✅ 核心能力 |
| **谁批准了什么** | ❌ 不负责 | ✅ 审计链 |
| **多 agent 统一权限** | ❌ 不负责 | ✅ 核心能力 |

两点补充：

1. **"Git 只管已提交的内容"这个说法不准确** —— Git 本来就能查看和恢复工作区、暂存区的未提交改动。准确的说法是：
   **Git 管理仓库里的文件状态，但不提供统一的 Agent 操作审批与副作用记录。**
2. cocraft **不替代 git**：`confessional_git` 只在"你提交之后、旧内容确实已进 git 对象库"时清理本地旧版；未跟踪 / 未提交的一律保留。
   规划中的方向是**深度集成**（任务开始时记录分支 / commit / 工作区状态，任务结束后把操作记录与 `git diff` 关联，确认后再交给你 commit）——**这还没做**，写在这里是为了说清方向。

## 常见问题

**Q：它会不会把我的文件删了？**
A：删除类命令里，**★ 级可再生成目标**（构建产物 / 缓存 / 日志 / 临时）会**先隔离再自动放行**；源码、配置、git 跟踪文件，以及关机 / 杀进程 / 格式化 / 注册表删除一律要你确认。
它是**尽力而为的安全网**：识别不出目标、目标太大、超出能力范围时会明确说"这次没能保住"——**不假装成功**。重要目录仍建议配合 git 与备份。

**Q：和 Git 重复吗？**
A：不重复。Git 管仓库里的文件历史（包括未提交改动），**不负责** Agent 操作审批、删除前复制、跨 agent 权限与操作归属；cocraft 管后者，长期版本仍交给 git。

**Q：是不是"可视化 Git"？**
A：不是。它建在**隔离区 + 内容寻址快照**上，**不依赖 git**：普通文件夹、未跟踪文件、被 `.gitignore` 忽略的文件、仓库外的文件都能保。git 只在"清理旧版"时作为归档依据。

**Q：怎么证明"记录没被改过"？**
A：审计链是 append-only + **哈希链**：改掉任何一条都会**断链**（面板显示「第 N 条断裂」+ 原因）。导出后可用独立脚本**离线复核**（JSON / CSV / 原始日志，含归档）；需要时用系统 OpenSSH **签名导出**。
准确说法是「**能检测篡改**」——签名证明"这份是谁给的、之后有没有变"；如果整条链被本地高权限进程删除，单靠链本身查不出来（这是已知边界）。

**Q：能撤回所有操作吗？**
A：**不能**。文件级的删除 / 覆盖 / 改名在识别范围内可恢复；**数据库写入、远程 API 调用、云端删除、部署、已经发出的网络请求**不可撤销。它是安全网，不是事务系统。

**Q：要不要注册 / 联网？**
A：不要账号。**默认全程本地**：cocraft 自己不上传代码或文件；只有你配置的模型调用会联网。
团队版可选用「共享目录 / 团队节点 / 中继」，同步的是**端到端密文**（密钥在你们手里，我们看不到明文）；中继能看到密文大小、时间与不透明 ID 这些最少元数据。

**Q：数据会不会上传到你们服务器？**
A：**默认不会**。只有你们**主动开启**团队版中继时，才会有**密文**经过；我们不保管密钥、也解不开。
被攻陷的终端仍可能泄露明文，加密保护的是传输与存储 —— 这两点我们在文档里写清，不含糊。

**Q：支持哪些 agent？**
A：OpenCode，以及任何支持 ACP 的 agent（Codex、Claude Code、OpenCode 自带 ACP、dsh 等）；可在面板里扫描本机或直接 npm 安装。

**Q：收费吗？**
A：**个人使用免费，并包含全部安全能力**（撤销 / 隔离 / 权限 / 本地审计）。
团队版（成员权限 / 集中策略 / 多人审批 / 审计汇总 / 签名报告）在规划中，细节尚未定价。
原则：**不拿"安全"做付费墙** —— 安全能力免费开放，靠团队治理与协作变现。

**Q：开源吗？**
A：核心计划开源（许可证待最终确定）；团队版功能会单独授权。发布前补 `LICENSE` 与第三方许可说明。

**Q：为什么只有 Windows？**
A：先把一个平台做透。Windows 上已有多款多 agent 工作台，但它们大多把隔离建在 git 上；我们专注**不挑目录的操作层护栏**，所以先做 Windows。

**Q：安装包为什么没签名？**
A：证书暂未取得；当前用 SHA256 校验 + 明确说明代替。介意的话可自行从源码构建。
