# 商业模式：开源核心 + 团队版（open core）

> 状态：**草案（2026-10-23），待拍板**。
> 结论先行：**个人永久免费（含全部安全能力），团队版收费；收费点是「团队才需要的能力」，不是许可证义务。**
> 配套文档：`docs/LICENSE-选项对比.md`（许可选择）、`docs/路线图-2026Q4.md`（阶段与门票）。
> ⚠ 本文是商业/工程权衡，不是法律意见；真收费前找律师过一遍合同与许可条款。

---

## 0. 一句话

> **看得到，免费；管得住、交得出去，收费。**

- 免费版：一个人、一台机器，全部安全能力（撤回 / 隔离 / 权限 / 本地审计）；
- 团队版：多成员汇总、集中策略、防篡改审计、可验证导出、多机、支持与合规材料。

---

## 1. 前提与边界

| 项 | 结论 | 理由 |
| --- | --- | --- |
| 个人用户 | **永久免费**，含全部安全功能 | 安全能力是招牌，收费会毁信任；个人也付不起 |
| 团队 | 按席位/团队收费 | 团队有预算，且需要汇总/策略/证据 |
| 收费载体 | **团队功能（闭源模块）**，不是"许可证限制" | 许可证限制"公司内部使用"既难定义又难执行 |
| 账号体系 | **不做** | 本地优先、数据不出机；账号=云=运维成本=信任成本 |
| 授权方式 | **离线 license 文件**（签名 + 席位 + 到期） | 不联网也能验证；符合"不上云"定位 |
| 数据归属 | **永远是用户的**，付费也不扣数据 | 导出永远可用；否则会被骂"绑架" |
| 免费门槛 | 小团队（≤3 人或年营收 < 100 万）免费 | bottom-up：先让人用起来，再谈钱 |

## 2. 三种收费模型（选错会同时得罪社区和客户）

| 模型 | 怎么收钱 | 个人免费 | 团队会付吗 | 主要问题 |
| --- | --- | --- | --- | --- |
| **A. 开源核心 + 专有团队版**（open core） | 团队功能闭源，不买就没有 | ✅ | ✅ 有明确付费物 | README 必须写清哪部分是开源、哪部分是商业许可，否则被说"假开源" |
| **B. AGPL + 商业双许可** | 企业不接受 AGPL → 买商业许可 | ✅ | ⚠ **AGPL 不限制公司内部使用**：一个团队内部自己用是免费的 | 收入靠"合规恐惧 + 支持 + 专有模块"，不是靠授权义务 |
| **C. "个人免费、商用收费"写进许可证** | 商用需购买授权 | ✅ | 靠自觉 + 抽查 | **不是开源**；"个人/商用"边界模糊（自由职业者接单算谁）；执行成本极高，社区反感 |

### 2.1 最关键的一条误解

> **AGPL 管的是"分发"和"对外提供服务"，不管"公司内部自己用"。**

- 公司内部 10 个人用 AGPL 软件干活、不对外分发 → **法律上不欠你钱**；
- 只有"把修改版作为网络服务提供给外部"才触发 §13 的开源义务；
- 所以：**想靠 AGPL 向团队收钱，收不到。** 团队付费必须来自"团队才需要的能力"（A）或"合规/支持"（B 的补充）。

### 2.2 推荐组合

**A 为主 + B 作为补充**：

1. 核心（`backend/`、`frontend/`、`tools/`）→ **AGPL-3.0**（个人真开源、可自建、可改）；
2. 团队模块（`enterprise/`，独立目录/独立进程）→ **商业许可**（不随免费版分发）；
3. 不接受 AGPL 的公司 → 买**商业许可**（同一份核心，双许可；你是唯一版权人，合法）；
4. 团队模块与核心保持**进程边界**（通过本地 HTTP/CLI 通信），避免"链接"争议，也方便单独授权。

> 如果你更想"全都开源"，那就走"FSL/BSL + 卖服务"，但那条路的收入更慢、更依赖咨询。

## 3. 功能切分（免费 vs 团队版）

原则：**安全能力永远免费；团队版卖"汇总、策略、证据、支持"。**

### 3.1 永久免费（个人版 / 社区版）

| 能力 | 说明 |
| --- | --- |
| 多 agent 并行 / 工作流 / 画布 / 阶段 | 编排是入场券，不收费 |
| 撤销这一轮（工作区快照 + 行级 diff） | 招牌能力 |
| 破坏性操作隔离区 + 恢复 | 招牌能力 |
| 权限 5 档 + 逐条审批 + 节点级 trust + per-agent 上限 | 招牌能力 |
| **本地审计时间线**（谁、什么命令、谁批的、结果） | 看得到 |
| **单机审计导出 JSON / CSV** | 数据归用户 |
| 单机运行、不登录、自带 Key | 定位 |
| 本机 agent 安装 / 更新 | 便利性 |
| **多 Key 凭据**（同一家多个账号 + 按 agent 选） | 多 agent / 多项目必备；也属于安全能力，免费 |
| **工作流模板库 + 导入 / 导出** | 5 分钟上手；模板文件可以手动发给同事 |
| 示例工作流 | 降低上手成本 |

### 3.2 团队版（付费）

| 能力 | 为什么团队才需要 | 备注 |
| --- | --- | --- |
| **多成员汇总**：一台机器上看全团队的任务/审批/结果 | 个人不需要"看别人" | 可先做"同一台机器多用户"再扩多机 |
| **共享模板库 + 策略下发**：统一"用哪套流程、给什么权限" | 团队要统一规矩，不靠每个人自己搭 | 与集中策略一起做 |
| **集中策略**：按项目/角色预设权限（只紧不松） | 团队要统一规矩 | 导入导出 + 版本号 |
| **防篡改审计**：哈希链 + 签名 + 可验证导出 | 给甲方/审计看 | 见 §4 |
| **审计保留期 / 归档 / 定期报告** | 合规与追溯 | 报告可 PDF/CSV |
| **多机 / 远程执行成员**（SSH） | 构建机、测试机、长任务 | 见路线图 P5 门票 |
| **团队看板 / 成本归属** | 谁花了多少、谁改了什么 | 依赖 worktree 隔离 |
| **SSO / 统一登录**（可选） | 企业采购 | 不做也别影响本地版 |
| **发票 / 合同 / SLA / 优先支持** | 采购流程 | 中国场景必须有 |

### 3.3 明确不收费（避免把招牌弄脏）

- 撤销、隔离、权限审批、本地审计查看；
- 安全相关的"救命"能力（恢复、冲突提示、破坏性拦截）；
- 用户自己的数据导出（单机 JSON/CSV 永久免费）。

> 一句话：**"保命"免费，"协作与交代"收费。**

## 4. 审计要做到"能卖"：四条硬要求

补审计时按这个做，**现在便宜、以后很贵**：

### 4.1 身份（Who）

每条记录必须能回答：**哪个成员 / 哪个 agent / 哪台机器 / 哪个会话**。

```json
{
  "v": 1,
  "seq": 1024,
  "ts": "2026-10-23T10:00:00Z",
  "machine": "ws-01",
  "actor": { "kind": "agent", "id": "codex-node", "member": "m2", "role": "implementer" },
  "approver": { "kind": "user", "id": "local", "name": "owner" }
}
```

### 4.2 防篡改（哈希链）

```json
{
  "action": { "kind": "exec", "command": "Remove-Item -Recurse -Force D:\\ws\\dist",
              "targets": ["D:\\ws\\dist"], "destructive": true },
  "decision": "confirm",
  "result": "ok",
  "quarantine": "runtime/quarantine/3/20261023-1000",
  "prev": "sha256:9f2c…",
  "hash": "sha256:41ab…"
}
```

- `hash = sha256(canonical_json(record 去掉 hash) + prev)`；
- **链尾哈希**写进导出文件尾部；
- 校验脚本：`cocraft_audit_verify.py export.json` → 逐条重算，报"第 N 条断裂"。

### 4.3 可验证导出

导出文件头写清：

```json
{ "format": "cocraft-audit", "version": 1, "exported": "2026-10-23T12:00:00Z",
  "records": 1024, "tail": "sha256:…", "engine": "cocraft 0.2.x" }
```

- 免费版：单机导出（JSON/CSV，**不带签名**，但哈希链也在）；
- 团队版：**签名导出**（对 `tail` 用私钥签名），别人能验证"这份没被改过"。

### 4.4 数据归用户

- 导出永远可用（付费到期也不锁）；
- 不加密绑架、不上传云端；
- 删除自己的审计记录也允许（但会留下"删除"这条记录，谁删的、什么时候）。

## 5. 授权机制（离线 license）

### 5.1 文件格式

```json
{
  "v": 1,
  "product": "cocraft-team",
  "licensee": "XX 工作室",
  "seats": 5,
  "issued": "2026-11-01",
  "expires": "2027-11-01",
  "features": ["team.aggregate", "policy.central", "audit.sign", "support.priority"],
  "sig": "base64(RSA-SHA256(上面这些字段的规范化 JSON))"
}
```

- **验证用公钥**内嵌在程序里（只验签，不需要私钥）；
- 纯 Python 可用 `pow(sig, e, n)` 做 RSA PKCS#1 v1.5 验签（不需要第三方库）；
- 私钥只在你手里，离线签发；**不要用 HMAC**（密钥必须随程序发，等于没有签名）。

### 5.2 生命周期

| 状态 | 行为 |
| --- | --- |
| 有效 | 团队功能可用 |
| 试用（14 天） | 功能全开，带"试用"标识 |
| 到期 | **只读模式**：已有数据可看、可导出；不能新建团队任务；**绝不删数据** |
| 席位不足 | 提示"当前 6 人 > 授权 5 席位"，不阻断已有任务，只提示补授权 |

### 5.3 明确不做

- ❌ 不联网校验（本地优先）
- ❌ 不装后门 / 不远程禁用
- ❌ 不锁用户数据
- ❌ 不做账号体系（除非以后真做多机团队版）

> 单人项目经不起"授权翻车"的口碑事故；宁可靠功能和信任，不靠技术封锁。

## 6. 定价（人民币，先服务后订阅）

| 对象 | 价格 | 说明 |
| --- | --- | --- |
| 个人 | **¥0** | 永久免费，含全部安全能力 |
| 小团队 | **¥0** | ≤3 人 或 年营收 < 100 万（自行申报） |
| 团队版 | **¥99~199 / 人 / 年** 或 **¥1,999~4,999 / 团队 / 年** | 含汇总/策略/签名审计/支持 |
| 试用 | 14 天全功能 | 到期转只读，不删数据 |
| 服务 | **¥3,000~8,000 / 次** | 装 + 策略 + 演练 + 审计模板（现金流最快） |
| 加急/定制 | 按人日 | 别轻易承诺 SLA |

**中国企业采购的现实**：
- 要能**开发票**（个体户/公司主体注册后再卖）；
- 走**对公转账 + 合同/报价单**，别指望 Stripe；
- 报价单里写清"席位 / 期限 / 支持范围 / 数据不出机"。

## 7. 执行与反盗版

| 手段 | 用不用 | 说明 |
| --- | --- | --- |
| 功能边界（专有模块） | ✅ 主力 | 最有效、最不伤感情 |
| 离线签名 license | ✅ | 防误用、方便合规 |
| 席位提示 | ✅ | 温和提醒，不阻断 |
| 联网激活 | ❌ | 与"不上云"冲突 |
| 代码混淆/加壳 | ⚠ 可选 | 只防君子，成本高，可能被杀软误报 |
| 法律追责 | ⚠ 备用 | 只对"拿去卖"的竞品用，不对普通用户 |

**判断标准**：任何防破解手段，如果会误伤正常用户或让杀软报警，就不做。你的品牌是"可信"，不是"防贼"。

## 8. 风险清单与对策

| 风险 | 概率 | 影响 | 对策 |
| --- | --- | --- | --- |
| **免费骑乘**（公司内部大规模用免费版） | 高 | 收入少 | 团队功能与支持才是付费点；不追着个人收费 |
| **"假开源"指控** | 中 | 口碑 | README 明确目录边界；`enterprise/` 单独许可；核心真开源 |
| **AGPL 吓跑企业** | 高 | 采用率 | 提供商业许可（双许可），并在 README 写清"企业可买许可" |
| **单人 SLA 撑不住** | 高 | 退款/差评 | 先卖服务（项目制），订阅只承诺"工作日邮件支持" |
| **fork 出去做竞品** | 中 | 分流 | AGPL 逼它开源；商标政策禁止用你的名字；差异化在团队模块与支持 |
| **license 被破解** | 中 | 收入 | 不追求强防；靠价值与合规，不靠加密 |
| **审计数据泄露（我们的 bug）** | 低但致命 | 信任崩塌 | 本地存储、不上传、导出由用户触发；发布前做安全自查 |
| **发票/主体问题** | 中 | 无法收款 | 提前注册个体户/公司；先服务后订阅 |
