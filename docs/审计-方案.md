## 0. 为什么先做这个（而不是先加 CSV）

原来的「导出审计」是**前端从页面内存拼**的（`frontend/js/20-collab.js` 的 `collabExport()` 只读 `COLLAB.run`）：

| 问题 | 后果 |
| --- | --- |
| 数据源是 `runtime/state/_orchestrator/runs/*.json` | 改一下文件就能改"谁批准了什么" |
| 页面刷新 / 换台机器 | 历史导出不了 |
| 没有连续性证明 | 交不出"这份记录没被改过"的证据 |

所以先立**服务端权威记录**（append-only + 哈希链），CSV / 面板显示都是它的消费者。

## 1. 数据结构

落盘：`runtime/state/_audit.jsonl`（**只追加**，不重写、不压缩；`runtime/` 已在 `.gitignore`）

```jsonc
{
  "v": 1,
  "seq": 1024,                                   // 自增，链内唯一
  "ts": "2026-10-24T20:11:02.123Z",
  "tsu": 1792843862.123,                          // 筛选/排序用（不牺牲可读性）
  "machine": "LAPTOP-XXXX",
  "actor":    {"kind":"agent","id":"codex-node","name":"实现者","member":"m1","role":"implementer","engine":"codex-node"},
  "approver": {"kind":"user","id":"local","name":"owner"},     // 没人批准就是 null
  "action":   {"kind":"execute","title":"运行命令","command":"Remove-Item -Recurse -Force D:\\ws\\dist",
               "targets":["D:\\ws\\dist"],"destructive":true},
  "decision": "once",                             // once|always|reject|restore|drop|undo
  "result":   "ok",                               // ok|denied|timeout|failed|skipped
  "quarantine": "3/20261024-2011",                // 隔离记录 id（没有就空 = 这次没保住）
  "source":   "collab",                           // collab|ccagent|snapshot|panel|manual
  "via":      "ui",                               // ui（面板点的）| api（本机接口调的）| system（程序内部）
  "ref":      {"run":"…","member":"m1","perm":"operm_…","chat":"7","aid":"11","scope":"","ts":""},
  "note":     "by=owner · 隔离 2 项 / 未保住 1 项",
  "prev": "sha256:9f2c…",
  "hash": "sha256:41ab…"
}
```

**哈希**（与商业模式 §4.2 一致）：

```
hash = sha256( canonical_json(record 去掉 hash) + prev )
canonical_json = json.dumps(obj, sort_keys=True, separators=(",",":"), ensure_ascii=False)
链首 prev = sha256:000…0（GENESIS）
```

## 2. 接口（本地路由，不走上游代理、无登录、不联网）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/audit/list?limit=80&source=&run=&member=&chat=&aid=&actor=&approver=&decision=&result=&since=&until=` | 最近记录（新 → 旧） |
| GET | `/audit/stats` | 条数 / 字节 / 坏行 / 首尾 seq / 链尾 |
| GET | `/audit/export?…&download=1&format=json\|csv` | 可验证导出（文件头 + 记录 + 链尾）；`format=csv` 一律当文件下载（带 BOM，Excel 直接开；链尾/条数放响应头 `X-Audit-Tail` / `X-Audit-Records`） |
| GET | `/audit/report?…&download=1` | **一页报告**（Markdown）：结论分布 + 破坏性逐条 + 明细（`download=1` 出 `.md`） |
| POST | `/audit/archive` | **手动归档**（`{maxMb?, keepMb?}`）；平时追加超阈值会自动归档 |
| POST | `/audit/verify` | `{}` = 校验本机整条链；`{items:[…]}` = 校验别人给的导出；`{subset:true}` = 区间导出 |

导出的文件头（§4.3）：

```jsonc
{"format":"cocraft-audit","version":1,"exported":"…","records":1024,"tail":"sha256:…",
 "engine":"cocraft <版本>","machine":"…","filters":{…},
 "chain":{"ok":true,"gaps":0,"subset":false,"first":1,"last":1024,"anchor":"","genesis":"sha256:000…"},
 "items":[…]}
```

独立脚本（给别人复核用，不需要装面板）：

```bat
python tools\cocraft_audit_verify.py 下载\cocraft-audit-2026-10-24T12-27-06.441Z.json
python tools\cocraft_audit_verify.py runtime\state\_audit.jsonl --quiet
:: 退出码 0 = 通过 / 1 = 有问题（可进 CI）
```

### 2.1 面板里怎么看（`ui 0.2.39`）

| 位置 | 内容 |
| --- | --- |
| 「权限 ▾ → 信任面板…」→ **审计链** 一节 | `链完整 · N 条` / `第 N 条断裂`；一行写清 `seq 1..N · 最后 <本地时间> · 坏行数`；断裂时**逐条列出第几条 + 原因** |
| 同节的「重新校验」 | `POST /audit/verify`，通过 → 普通横幅；**不通过 → 常驻横幅**（不一闪就没） |
| 同节的「导出」 | `GET /audit/export` → 下载 `cocraft-audit-<时间>.json`（带文件头 + 链尾，可离线复核） |
| 同节的「导出 JSON / 导出 CSV / 导出报告」 | JSON = 可验证导出（文件头 + 链尾）；**CSV = 留档**（列头定死、Excel 直接开，**每行仍带 `prev`/`hash`**，所以也能逐行重算）；**报告 = 一页 Markdown**（结论分布 + 破坏性逐条 + 明细） |
| 标题右侧 | `链完整 · N 条（含归档 X 条 / Y 个文件）` —— 归档过的量也写清楚，不是"看不见了" |
| 本地协作工作台的「导出审计」 | **改成走 `/audit/export?run=<runId>`**（服务端权威链），不再由前端内存拼；「导出记录」保留原来那份运行记录 |
| 「AI 成员改了什么」一节（C3） | 群聊 AI 成员**每次派活收尾**把"这一轮改了哪些文件"写进审计链（`source=ccagent` / `action.kind=files`），面板按 `GET /audit/list?source=ccagent&kind=files` 列出：谁 · 改了哪几个文件 · `+增 ~改 -删 ⇄重命名` · 时间 |

⚠ **C3 只记文件名 + 计数，不存内容**：轮快照是 `with_content=False`（不占磁盘），所以**没有一键回滚**。
要回滚必须先把内容也进内容仓（`take_snapshot(with_content=True)`），那是另一个决定（磁盘换能力）。

⚠ 时间显示用 `ts`（ISO，UTC）→ 本地时间；**不是**空值就显示空，不乱写。

## 3. 写入点（谁在写链）

| 位置 | 场景 | decision / result |
| --- | --- | --- |
| `backend/cocraft_agents.py` `_perm_log_add()` | 群聊：拥有者批准 / 拒绝 / 超时 / 发不出去 / 没上下文 | `once·always` → `ok`；拒绝 → `denied`；超时 → `timeout`；发不出 → `failed` |
| `backend/orchestrator.py` `_ask_permission()` | 工作台：待批权限的最终结论（**含超时与取消**） | 同上；人工批准才写 `approver`（`local/owner`） |
| `backend/engines/opencode.py` `handle_api()` | **面板里单会话审批**（OpenCode 引擎走反代，只能在转发的之前截） | `once/always` → `ok`；`reject` → `denied` |
| `backend/engines/acp/service.py` `_ask()` 收尾 | **面板里单会话审批**（ACP 引擎；含 30 分钟超时无人答） | 同上；超时 → `timeout` 且 `approver=null` |
| `backend/server.py` `/quarantine/restore` `/quarantine/drop` | 从隔离区恢复 / **永久删除**恢复点 | `restore` / `drop` |
| `backend/server.py` `/snapshot/undo` | 「撤销这一轮」 | `undo` |

### 3.1 「谁干的」：`via`（人点的 vs 脚本/agent 调的）

本机接口**没有鉴权**（只认 localhost），所以光看 `actor` 分不出"人点的"和"agent 用 HTTP 调的"。
记录里多一个 **`via`**：

| `via` | 含义 | 谁写 |
| --- | --- | --- |
| `ui` | **面板里点的**（`actor=user/local`） | 面板的 `fetch` 统一带请求头 `X-Cocraft-UI: 1` |
| `api` | **本机 HTTP 接口调的**（`actor=system/local-api`，名字写「本机接口（未经面板）」） | agent / 脚本直接 curl 没有这个头 |
| `system` | 程序内部（群聊桥、ACP 引擎、归档等） | 默认值 |

⇒ 看到 `via=api` + `actor=system` 就说明**不是人在面板上点的**（可能是 agent 自己调的接口）。
⚠ 这只是"**归因**"，不是"**拦截**" —— 本机接口仍然没有鉴权（见 §10 的边界）。

## 4. 口径（刻意不做的事，别当成 bug）

1. **策略自动放行不入链**：按权限等级 / 节点 `trust` 自动放过的读写执行不写。
   理由：IO 放大（每个命令一条）+ "谁批准了"本来就只该收**人的决定**；破坏性操作**永远**要人确认，不受影响。
   这些自动操作在活动流（`/ccagent/activity`）里能看到。
2. **不记"正在等"**：只记结论。等待期间进程被杀 → 没有记录（确实没有决定）。
3. **不记成员正文**：只有决定 + 命令原文 + 目标路径 + 隔离记录 id。
4. **fail-open**：链写不进去只影响"留痕"，**绝不阻断**审批/执行流程（回归里有一条专门盯它）。
5. **不自动清理成"看不见"**：主文件超过 4 MB 会把最旧的一段移进 `_audit-archive/`，
   **归档这件事本身写进链**（`action.kind=archive`）；读/校验都把归档一起算（见 §7）。
6. **测试隔离**：`backend/audit.py` 认环境变量 **`COCRAFT_AUDIT_FILE`**，`tools/run_suite.py` 统一指向
   `runtime/logs/suite/_audit_test.jsonl`；`acp_api_test` / `acp_events_test` / `acp_engine_ui_test` /
   `orchestrator_test` / `perm_audit_test` / `audit_chain_test` 各自 `audit.set_file()` 到临时目录。
   **不许让测试写真实链**（踩坑 #36 同一类）。

## 5. 校验与已知边界

- `verify()` 逐条**重算哈希**，并要求每条的 `prev` 能在链内解析到 → 改内容、删中间、乱序、撕裂行都会报出来（带 `第 N 条 / seq / 应为 / 实为`）。
- **区间导出**（按时间/成员/任务筛选）必然有 `gaps`；它的**首条 `prev` 指向范围外**，所以：
  - 校验时把那条 `prev` 当"锚点"（`chain.subset=true`、`chain.anchor`），否则任何筛选导出都会假报断；
  - 代价：**区间导出的第一条无法就地证明自己衔接在哪** → 需要在完整链上复核。这是已知边界，不是 bug。
- 多进程写：`server.py` 与群聊桥会同时写 → `msvcrt` 锁 `.lock` 文件；拿不到文件锁退化成进程内锁（日志不拖死业务）。
- 文件尾部被撕（断电）：坏行留在原地、`verify` 如实报"坏行"，**不会静默丢弃**。

## 7. 保留期 / 归档

主文件 `runtime/state/_audit.jsonl` 只追加；**超过阈值**（默认 `4 MB`，env `COCRAFT_AUDIT_ROTATE_BYTES`）
就把最旧的一段移进 `runtime/state/_audit-archive/<首seq>-<末seq>.jsonl`，主文件只留最近约 `1 MB`
（env `COCRAFT_AUDIT_KEEP_BYTES`）。每次追加后顺手 `stat` 一次，超了才动手；`max_bytes=0` = 关掉。

| 保证 | 做法 |
| --- | --- |
| 归档**不改内容** | 逐字节搬原始行（哈希当然不变），归档文件之后不再改 |
| 跨文件**仍是同一条链** | `_read_lines()` 读「归档（按文件名顺序）+ 主文件」，`verify()` 直接全链校验、`gaps=0` |
| 不双计 | `seq` 重复时保留先读到的那份（切换瞬间可能短暂重叠） |
| **不偷偷删** | 归档动作本身写一条 `action.kind=archive` 记录（带归档文件名与 seq 区间），落在主文件里 |
| 手动也能归档 | `POST /audit/archive {maxMb?, keepMb?}` |
| 看得见 | `GET /audit/stats` 回 `archived {files, records, dir, latest}`；面板标题写「含归档 N 条 / M 个文件」 |

校验：`python tools\cocraft_audit_verify.py runtime\state\_audit.jsonl` 会**自动带上旁边的归档目录**
（输出 `主文件 + 旁边的归档目录一起校验`）。

### 7.1 一页报告

`GET /audit/report`（`download=1` 出 `.md` 文件）→ Markdown：范围 / 条数 / **链校验结论** / 链尾 /
经人批准次数 / 破坏性操作次数 / 文件改动轮次 · 结论分布（决定 / 结果 / 来源）· **破坏性逐条**（命令、谁批的、是否隔离）
· 明细表（最近 200 条）。**只含决定 / 命令 / 目标，不含成员正文。**

## 8. 签名导出（可选，团队版那一层）

链证明「没被改过」；签名证明「**这份文件是谁给的**」。用系统自带的 OpenSSH，不自己实现密码学
（纯标准库没有非对称签名，自己搓容易悄悄写错 → 白签）。

```bat
python tools\cocraft_audit_sign.py keygen                     :: 一次性：~/.cocraft/audit-key（私钥只在本机）
python tools\cocraft_audit_sign.py sign   cocraft-audit-xxx.json   :: 生成 <文件>.sig（SSHSIG，命名空间 cocraft）
python tools\cocraft_audit_sign.py verify cocraft-audit-xxx.json --pub audit-key.pub
```

| 项 | 说明 |
| --- | --- |
| 命名空间 | `cocraft`（签、验必须一致，防"拿别的用途的签名来冒充"） |
| 对方怎么验 | 拿到「导出文件 + `.sig` + 公钥」→ `verify`；Linux / macOS 上 `ssh-keygen -Y verify` 一样能验 |
| 私钥放哪 | 默认 `%USERPROFILE%\.cocraft\audit-key`，**不进仓库、不进 `runtime/state/`、不进安装包** |
| 免费版 | 链 + 校验 + 签名**工具**都随包（自己生成密钥即可）；团队版的价值在「集中策略 / 多成员汇总 / 支持」，**不靠锁签名** |
| 边界 | 签名只证明"文件自签名后未被改"；**不证明链本身完整**（那是 `cocraft_audit_verify.py` 的活，两个都跑） |

## 10. 谁能删 / 能恢复多久 / 占多少存储（边界表）

### 10.1 删除留痕：现在谁能删什么

| 删什么 | 现在有没有入口 | 留痕 |
| --- | --- | --- |
| **审计记录本身** | **没有**（没有删除 API / 按钮）→ 所以"删了谁"这条目前不适用 | — |
| **隔离区记录**（恢复点） | 有：面板「隔离区 → 删除」/ `POST /quarantine/drop` | 已进链：`kind=drop`，`via=ui` 时 `actor=user/owner`；`via=api` 时 `actor=system/local-api`（说明不是人点的） |
| **恢复点内容**（隔离的备份文件） | 同上（删记录即删副本） | 同上 |
| **快照**（每轮） | 有：`POST /snapshot/drop`（没有单独留痕记录，只有 `KEEP` 自动裁剪） | ⚠ 未单独留痕（下一步可补） |
| **审计归档文件** | 没有入口；手动删磁盘就会**校验报断**（链尾对不上） | 删了会在 `verify` 里暴露 |

⚠ **真正的边界（必须说清）**：本机接口**没有鉴权**（只认 localhost），而且 `runtime/state/` 是普通文件。
→ **一个拿到 shell 权限、且能写这个目录的 agent，可以直接删/改 `_audit.jsonl`**。应用层拦不住；
   能发现的只有"改内容/删中间/删归档"（哈希链对不上），"整条链被删掉"**发现不了**（没有链外锚点）。
   要堵住这个口子，得做「链尾哈希写到外部（注册表 / 另一台机 / 每日快照）」——**没做**，别当成已有能力。

### 10.2 恢复能力：能回到多久以前

| 机制 | 时间窗口 | 存储占用 | 硬上限 |
| --- | --- | --- | --- |
| **隔离区**（破坏性操作放行前复制原件） | **不限时间**（文件一直在，直到你手动删） | 原件大小 | 单个文件 **64 MB** / 单次 **512 MB** / 单次 **400 个目标**；**没有总量上限、不自动清理** |
| **「撤销这一轮」**（每轮快照，设置里默认**关**） | **最近 40 轮 / 每个会话**（**按次数，不按天**） | 内容仓（内容寻址去重，同一份内容只存一次） | 每 scope 40 次；全局内容仓 **2 GB 硬上限**（超了丢最旧快照回收，但每 scope 至少留 **5** 次） |
| **群聊派活轮快照**（C3 用） | 最近 40 轮 / 每个 群×成员 | 极小（**只存路径 + 哈希，不存内容**） | 同上 40 次 → **只看得到改动，不能回滚** |
| **审计链** | **永久**（归档后仍可校验） | 约 **0.6 KB / 条**（命令原文另计） | 主文件 **4 MB** 到顶就归档；**归档不自动删 → 长期会一直长**（要自己定期清） |

**实测占用（本机 2026-10-25）**：`runtime/snapshots` **106 MB**（4 个 scope，其中一个 30 次快照；内容仓 105.5 MB / 387 块）、
`runtime/quarantine` **0**、审计链 **0**（还没人批准过）。

### 10.3 一句话

- **"能恢复多久"取决于哪个机制**：隔离区 = 不限时间（占空间）；撤销这一轮 = **最近 40 轮**（不是天数）；群聊改动 = 只能看不能回滚。
- **"占多少"**：快照最占（内容仓 2 GB 上限，实测本机 106 MB）；隔离区按原件大小、不自动清；审计链很小（0.6 KB/条）。
