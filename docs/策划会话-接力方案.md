# 策划会话 · 接力（Handoff）方案

> 问题（用户 2026-11-09）：策划会话 + 策划 agent 在**上下文满了**以后，能不能用 **md 文件接力**？
> 还要考虑**更换策划 agent**（换模型 / 换厂商）的情况。
> 相关：`docs/策划会话-方案.md`（策划会话本体）。

---

## 0. 一句话

> **能，而且应该用 md —— 但 md 只做"接力包"，不做"执行源"。**
> 可执行的事实（计划 / 运行状态）永远在 `plan.json` 与运行记录里；md 负责把人话、决策与下一步带给下一棒。

---

## 1. 三种接力场景（别混着设计）

| 场景 | 触发 | 下一棒是谁 | 需要什么 |
| --- | --- | --- | --- |
| **A. 同一 agent，上下文满** | `context.used / size ≥ 80%`（或估算） | 同一个 agent 的**新会话** | 计划 + 交接包；不需要重新认识用户 |
| **B. 换策划 agent** | 用户手点 / 原 agent 不可用 | 另一个引擎/模型 | 交接包 + **能力复核** + 明确的"别重新设计"约束 |
| **C. 崩溃 / 面板重启** | 进程没了 | 任意 | 计划 + 最近一次交接包 + 运行状态（可能有 running 残局） |

⚠ 三种场景共用同一份交接包格式，但 **B 要额外做能力复核**（见 §6）。

---

## 2. md 与 json 的分工（关键边界）

| 文件 | 角色 | 谁写 | 谁读 |
| --- | --- | --- | --- |
| `plan.json` | **唯一可执行真相**（阶段/成员/权限/预算） | 策划 agent 提交 + 后端校验 | Runner / 画布 / 会话 |
| `RUN.json`（运行记录） | 执行事实（谁跑了、改了哪些文件、审批结论） | Runner | 会话 / 报告 |
| **`HANDOFF.md`** | **接力包**：目标、决策、未决、下一步、别做 | 面板模板 + 策划 agent 补一段 | 下一棒的 agent（作为首条消息注入）+ 人 |
| `PLAN.md` | 计划的**人读版**（与 plan.json 同源渲染） | 后端渲染 | 人 / agent |
| `events.jsonl`（已有审计链） | 证据 | 系统 | 审计导出 |

> **不允许**从 `HANDOFF.md` 里解析出执行参数（防止 md 被手改后跑出别的东西）。
> 一致性检查：md 里的"计划版本号"必须等于 `plan.json.version`，否则提示"交接包过期"。

---

## 3. 目录

```
runtime/state/_planner/<planner_id>/
  plan.json          # 计划（版本化，后端校验）
  PLAN.md            # 计划的人读版（自动渲染，只读）
  HANDOFF.md         # 接力包（每个检查点覆盖写；历史版本另存 handoff/<ts>.md）
  meta.json          # {agent, model, phase, planVersion, runId, context, updatedAt}
  handoff/
    20261109-1530.md # 每个检查点留一版（可回看"上一棒是怎么想的"）
```

`planner_id` 与"策划会话"绑定；换 agent = 同一 `planner_id`，只换 `meta.agent`，**接力包不变**。

## 4. `HANDOFF.md` 模板

```markdown

run_id: run_20261109-1502_7c1d

model: deepseek-flash

handoff_no: 2             # 第几棒
---

## 1. 用户目标（原话）
给登录模块加短信验证码，并通过现有测试。

- 不要自己批权限、不要自己应用改动
- 不要扩大预算（成员 8 / 阶段 8 / 60 分钟）

- 计划：`plan.json` v3 / `PLAN.md`
- 运行：`runtime/state/_orchestrator/runs/run_…7c1d/`
- 审计：`runtime/state/_audit.jsonl`（`ref.planVersion=3`）
- 上一棒：`handoff/20261109-1410.md`
```

**篇幅：分三层，不是一刀切 8 KB**

| 层 | 内容 | 大小 | 是否注入 |
| --- | --- | --- | --- |
| **CORE（必带）** | 目标原话（截断）/ 硬约束 / 已决定 / 当前进度 / 下一步 / 别做 | **6~8 KB** | ✅ 总是 |
| **REFERENCE（按需）** | 计划表（阶段×成员×权限）、未决问题细节、改动文件 top 20、风险 | 8~24 KB | ✅ 预算够就带，否则只带表头 |
| **EVIDENCE（永不内联）** | diff / 日志 / 审计片段 / 历史交接全文 | 不限 | ❌ 只给 id / 路径，agent 用 `planner handoff show --section` 取 |

**为什么 8 KB 不是"总量"，而是"核心预算"**：

- 8 KB ≈ 2,300 个汉字 ≈ **1.8~2k tokens**（中文按 1 token ≈ 1.2 字估），对 128k 窗口只占 **1.5%**；
- 真正的风险不是"装不下"，而是**密度被稀释**：把日志、diff、原话全文塞进去，新 agent 会抓不住"哪些是约束、哪些是历史"；
- 需要完整信息时，让 agent **按段取**（CLI），比一次性灌进去更可控。

**动态预算**（`inject_budget = clamp(2% × 模型上下文, 6 KB, 24 KB)`）：

| 模型上下文 | 注入上限 | 说明 |
| --- | --- | --- |
| 32k | 6 KB | 小窗口：只带 CORE；REFERENCE 靠 CLI 取 |
| 128k | ~10 KB | CORE + 计划表 |
| 1M | 24 KB | CORE + REFERENCE 全带 |

**超预算时的裁剪顺序**（必须固定，别让模型自己决定）：
1. 删 EVIDENCE（本来就不在 md 里）；
2. 截断"用户原话"（保留首段 + 约束关键词）；
3. 改动文件列表只留 top 20 + 计数；
4. 历史交接只留"第 N 棒一句话摘要"；
5. 仍然超 → 把 REFERENCE 移到 `handoff/<ts>.full.md`，注入里只留指针。

> 一句话：**8 KB 是"必须记得的东西"的上限；不是"所有东西"的上限。**

## 5. 何时写、何时读、怎么注入

| 时机 | 动作 |
| --- | --- |
| 进入/离开任一阶段、计划版本 +1、运行结束 | **写**交接包（覆盖 + 留历史） |
| 上下文 ≥ 80%（或估算超阈值） | 写交接包 → 会话里提示「准备接力」→ **下一条消息**开新会话（用户无感，视图不断） |
| 用户点「换策划 agent…」 | 写交接包 → 停下当前会话 → 用新 agent 建会话 |
| 新会话第一条 | 注入 `【接力包 #N】` + HANDOFF.md + `PLAN.md` + 最近 3 条用户消息（保持语气） |
| 面板重启 | 读 `meta.json` + 最近一次交接包；若有 running 残局，先对账再继续 |

**注入方式**：与现有 `_reseed_text` 同类（拼在 prompt 前），但用固定标记 `【接力包 #N】`；
展示层已有 `strip_injected_prefix()`，把这段从"用户说的话"里剥掉（不然又会出现"我没输入过这段"）。

## 6. 更换策划 agent（重点）

### 6.1 流程

```
点「换策划 agent」
  → 若正在跑：先确认"取消当前运行"（不取消就不能换）
  → 写交接包（含"别重新设计"约束）
  → 校验新 agent：可用 / 模型清单 / 上下文大小
  → 用新 agent 建新会话，注入交接包
  → 在会话里显示一条系统提示：「已接力给 <agent>（第 N 棒）」
```

### 6.2 能力复核（换模型后必须做）

| 检查 | 为什么 |
| --- | --- |
| 新 agent 可用（命令/凭据/模型） | 换过去起不来最尴尬 |
| 上下文窗口大小 | 决定下一次接力阈值（别用同样的 80% 硬编码） |
| 是否支持 JSON 稳定输出 / 工具调用 | 计划 JSON 校验会拦，但要提前提示 |
| 计划里的成员引擎是否仍可用 | 换的是**策划** agent，不改成员；但引擎可能被卸载 |

### 6.3 换 agent 时**不要**做的事

- ❌ 不要把旧 agent 的全部聊天记录塞给新 agent（浪费上下文，还会让它重走弯路）；
- ❌ 不要自动"沿用旧 agent 的口头承诺"（以交接包的"已决定"为准）；
- ❌ 不要在运行中换（先取消，或等这一轮结束）。

### 6.4 换回来怎么办

`meta.json` 记录历任 agent；会话里可以点「换回 <agent>」—— 仍然走同一个交接包，不依赖旧进程。

---

## 7. 一致性与防漂移

1. **版本号对账**：`HANDOFF.md.plan_version` ≠ `plan.json.version` → 提示"交接包过期，已按当前计划渲染"；
2. **禁止 md 驱动执行**：`run start` 只读 `plan.json`；
3. **人工可编辑**：允许用户直接改 HANDOFF.md（比如纠正常识），下次写回时保留"用户备注"段；
4. **每棒留档**：`handoff/<ts>.md` 不覆盖，方便回看"哪一棒把预算改了"；
5. **入链**：每次写交接包记一条 `kind=handoff`（哈希 + 棒次 + 触发原因），不记正文。

## 8. 实施

| 阶段 | 内容 | 工作量 | 验收 |
| --- | --- | --- | --- |
| **P0** | `HANDOFF.md` 模板 + 手动「写交接 / 换 agent」按钮 + 新会话注入 | 3~4 天 | 手动写 → 换一个 agent → 新会话能接着干，不重新设计；**注入 ≤ 预算** |
| **P1** | 自动触发（80% / 估算）+ 版本对账 + 历史留档 + 展示层剥离 + **按模型上下文算预算** | 1 周 | 跑满上下文自动接力，用户只看到一条「已接力」提示；**超预算按固定顺序裁剪** |
| **P2** | 多棒链（`handoff_no`）、用户备注保留、`--section` 按段取、团队版可见「第几棒」 | 1 周 | 连续 3 棒后仍不丢约束；**新 agent 能复述目标/约束/下一步**（不一致即判接力失败） |

---

## 9. 风险

| 风险 | 缓解 |
| --- | --- |
| 交接包越写越长，反而吃掉上下文 | 三层预算（CORE 6~8 KB / REFERENCE 按需 / EVIDENCE 不内联）+ 动态上限 + 固定裁剪顺序 |
| 新 agent 不读交接包，重新问一遍 | 首条消息强约束 + 会话里显示"未遵守"提示（它重复提问时标红） |
| 交接包与计划漂移 | 版本号对账 + 计划永远优先 |
| 换 agent 后能力下降 | 换之前做能力复核；计划校验兜底 |
| 用户改了 md 但没生效 | 明确"md 不是执行源"，UI 标注"只影响接力叙述" |

---

## 10. 一句话总结

> **接力靠两样东西：`plan.json` 保证"事情不变形"，`HANDOFF.md` 保证"人话不丢失"。**
> 换策划 agent 只是换"下一棒的人"，不是换"比赛规则"——规则在文件里，不在模型脑子里。
