## 1. 他们的五个问题，逐条判定

| # | 他们的判断 | 我们的判定 | 处理 |
| --- | --- | --- | --- |
| 1 | 没有真正的多人协作管理 | **成立**（单机、无账号、无集中视图） | 不做云，做**最小团队闭环**（共享目录 + 只读汇总页，P1） |
| 2 | 缺 worktree 隔离 | **成立**（代码里没有任何 worktree 实现） | **P0 第一优先**（并行是核心场景，不隔离就是隐患） |
| 3 | 撤销 ≠ 沙箱 | **成立**（我们自己也这么写） | 不改定位，改**证明方式**：覆盖矩阵 + 恢复成功率量化（P0） |
| 4 | 审计 ≠ 企业合规 | **成立**（同机私钥、无集中留存、完整性未证） | 加**覆盖报告** + **外部落地（sink）**（P0/P1）；不宣称"不可篡改" |
| 5 | 成熟度 / 供应链风险 | **成立**（未签名、无 LICENSE、无 SBOM） | **P0**：打包 + 签名（或可复现构建）+ LICENSE + 第三方声明 + SBOM |

他们的**第 3、4、5 条不是"做功能"能解决的，是"出证据"能解决的** —— 这正好是三人团队能赢的地方。

## 3. 迭代计划（按优先级，不是按功能多少）

### P0 · 让 POC 能过（约 3 周 / 三人并行）

#### P0-1 worktree 隔离（并行不再互相覆盖）★最关键 ✅ **v1 已完成（2026-11-06）**

| 项 | 内容 |
| --- | --- |
| 做什么 | 每个成员一个独立工作区：**git 仓库 → `git worktree`**（分支 `cocraft/<run>/<member>`，并把**未提交改动**同步进去）；**非 git 目录 → 影子副本**（真复制；有文件数 / 体积上限） |
| 交互 | 跑完出「成员 × 文件」改动统计 → 每个成员列上「**应用回主目录**」（覆盖前先进忏悔室；主目录运行期间被改过 → 报冲突，确认后才 force）→ 也可「**清理隔离**」 |
| v1 边界 | 工作目录是**仓库子目录**时退回影子副本（`git status` 路径相对仓库根，v1 不做换算）；**不自动合并**；目录超限 / 只有一个成员 → `mode=off` + 明确原因（不假装隔离） |
| 验证 | `tools/isolation_test.py` **27 项**：独立目录 / 统计 / 应用 / 冲突拒绝 / force / 清理（worktree + 分支） / 影子模式不是硬链接 / 上限与单成员降级 |
| 风险 | 大仓库 worktree 慢、路径过长、submodule；影子副本对超大目录不适用（已用上限兜底） |

#### P0-2 审计覆盖报告 + 外部落地（回答"完整性"和"同机留存"）

| 项 | 内容 |
| --- | --- |
| 覆盖报告 | 每轮统计：工具调用 N 条、入链 M 条、**未观测 K 条**（如 agent 自己 `Start-Process` 起的进程）；`GET /audit/coverage?run=`；简报里加一节「本次未能覆盖的操作」 |
| 外部 sink | `POST /audit/sink`：把每条记录**追加**到用户指定的路径（另一块盘 / 网络共享 / U 盘），带 fsync；链尾哈希一并写入 → 本机文件被删也能对照 |
| 验收 | 杀进程后链仍完整到最后一笔；sink 文件尾哈希 = 本地链尾；篡改测试仍报「第 N 条断裂」；`audit_coverage_test` |
| 注意 | sink 只解决"另一处副本"，**不等于**集中审计；对外口径仍是"可检测篡改" |

#### P0-3 权限覆盖矩阵（证明"不是只在 UI 里设权限"）

| 项 | 内容 |
| --- | --- |
| 做什么 | `tools/perm_bypass_test.py`：pwsh `-Command`、`cmd /c`、`Start-Process`、`python -c subprocess`、`.ps1`、`.bat`、`node -e`、编码后的命令 → 逐条验证"被看到 / 被拦 / 明确未覆盖" |
| 产出 | 一张**公开矩阵**（哪些通道已覆盖、哪些不覆盖）；未覆盖的在运行时标 `unobserved` |
| 验收 | 矩阵进仓库；readme 引用；不出现"默认全拦"的表述 |

#### P0-4 恢复成功率量化（把"尽力而为"变成数字）

| 项 | 内容 |
| --- | --- |
| 做什么 | `tools/recovery_bench.py`：N 个场景（删文件 / 删目录 / 覆盖写 / 改名 / 未跟踪 / ignored / 仓库外 / 只读文件 / 超大目录）→ 自动测**恢复成功率、耗时、失败原因** |
| 产出 | `docs/恢复能力-实测.md`（可给客户/论文引用） |
| 验收 | 跑完自动生成表格；失败项如实列出 |

#### P0-5 发布物：签名 / LICENSE / SBOM

| 项 | 内容 |
| --- | --- |
| 做什么 | 打 `0.2.111` 安装包（VM 干净机 + 覆盖升级）；`LICENSE` + `THIRD-PARTY-NOTICES.md`；`packaging/sbom.json`（复用 `deps.lock.json` + 各组件 SHA256） |
| 签名 | 有证书就签；没有就**明确写"未签名 + SHA256 + 可复现构建步骤"**，并在 release notes 里给哈希 |
| 验收 | 干净机安装/升级/卸载；杀软行为记录；哈希可复核 |

### P1 · 小团队最小闭环（约 3~4 周）——**不做账号、不做云控制台**

> 定位更新（2026-11-06）：**明文不出机，团队只同步端到端密文**。详见 `docs/团队版-架构与路线.md`。
> 所以 P1 的"共享目录"里放的是**加密包**（AES-256-GCM，密钥在客户手里），不是明文审计。

#### P1-1 团队只读汇总（共享目录，密文包）

```
每台机器：POST /audit/export?format=bundle  →  <共享目录>/<机器名>-<日期>.cocraft-bundle
团队页：  GET /team?dir=<共享目录>  →  只读列出：机器 / 运行 / 审批 / 失败 / 恢复
```

- 没有服务器、没有账号、没有云端；权限沿用 Windows 文件权限；
- 汇总页**只读**（不能远程操作别人的机器）→ 先满足"看得见"，不碰"管得着"。

#### P1-2 工作流/模板分发

- 导出 `.cocraftpack`（工作流 + 角色 + 权限 + 可选技能/宏），导入即用；
- 模板库先做 3 个：实现→审查、实现→审查→测试、调研→审查。

#### P1-3 失败恢复的"可解释"

- 恢复失败时给三类原因：目标未识别 / 超出上限（超大目录）/ 已被他人覆盖；
- 面板提供"这次没能保住什么"的清单（已有雏形，补全场景）。

### P2 · 之后再说

- 工作流沉淀为技能 P1（`SKILL.md` 预览 → 人审 → 写入）；
- worktree 的合并 UI（cherry-pick / 逐文件挑选）；
- 诊断包、命令解析器加固；
- 团队版的"集中策略下发"（需要服务端，等有付费客户再谈）。

## 4. 明确不做的（写死，防止战线扩散）

| 不做 | 原因 |
| --- | --- |
| 云控制台 / SaaS 多租户 | 与"数据不出机"冲突；也不是我们三人能维护的 |
| SSO / SCIM / SOC2 | 企业采购门槛，但没有团队前不做 |
| 与 Linear / Jira 深度集成 | 他们是任务中枢，我们是执行层；导出 JSON 即可 |
| 聊天/IM、计费、插件市场 | 不影响"敢让它动电脑"这个卖点 |
| mac 移植 | 先把 Windows 做透（评估也认同这是我们的差异） |
| 自动合并 worktree | 冲突静默合并 = 事故 |

## 5. 目标客户与话术（按评估修正）

| 客户 | 我们怎么卖 | 不能说什么 |
| --- | --- | --- |
| **Windows 重度 AI 开发者**（第一优先） | "跨厂商统一权限 + 删除前隔离 + 普通目录可恢复" | 不说"唯一能撤销" |
| **2–15 人工作室 / 外包**（第二） | "每台机器装，交付时给客户一份**可复核的操作报告**" | 不说"统一的团队管理平台"（现在做不到） |
| **隐私敏感团队**（第三） | "本地运行、自带 Key、数据不出机" | 不说"企业级合规"（没有集中留存/身份） |

> 评估里那句"**Cocraft 可以承担额外的本地安全角色**"就是我们的正确位置：
> **不是替代 Paradev / Conductor / Codex App，而是和它们叠加**。

## 7. 验收门槛（自证，不自嗨）

1. POC 清单 **≥ 7/8**（第 6 项为"轻量团队视图"）；
2. 三个成员同仓库并行 **零覆盖冲突**；
3. 恢复 bench **成功率 ≥ 95%**（失败项有明确原因）；
4. 权限矩阵**覆盖所有已知通道**，未覆盖项在 UI 里可见；
5. 安装包可在**干净 Windows** 安装/升级/卸载，哈希可复核；
6. 审计链在**进程被杀 / 本机文件被删**后仍能证明"断在哪"。
