## 一、`cu macro`（`0.2.79`）

**为什么**：GUI 任务慢的根因是**步数 × 每步模型往返**（≥100 步 × 6–9 s ≈ 10–15 分钟），不是工具慢（10–150 ms）。

| 层 | 落地 |
| --- | --- |
| 核心 | `backend/computer/macro.py`：**从审计链提取**（只取成功动作；按 `ref.run` / 时间窗筛）、参数化、不存 hwnd、危险动作扫描、回放渲染、过期提示、回放统计 |
| CLI | `cu macro list/show/save/play/rm/export`；`save --from-run <id>` 或 `--from-audit --since 2h`；`play --set k=v [--dry-run] [--allow-danger]` |
| 回放 | 每步**翻成一条等价的 cu 命令**再跑（`_step_argv`）→ 同一套闸门 / 租约 / 审计；控件没找到会**等 200ms 重试一次**，仍不行再退回只用类名 |
| 审计 | 一条 `tool=macro_play`（宏名 / 步数 / 结果 / 毫秒），**参数值只哈希**；每步仍各自入链 |
| 面板 | 工具目录新增「**复用（宏）**」组（4 条）→ 共 **31** 个工具；`GET /cu/status` 多回 `macros` |
| 提示层 | `CU_CARD` 规则⑤：动手前先 `cu macro list`，有宏就回放，别从零探索 |
| 权限 | `macro play` = 动作；`list/show/save/rm/export` = 只读 |

**铁律**：宏**不能自己提权** —— 含危险词（发送/支付/删除…）或回车类快捷键（`CTRL+ENTER`）必须每次
`--allow-danger`，且这个判断**按当前步骤重算**（改 JSON 抹掉 `danger` 也没用）；每步仍过 gate。

**实测**：真窗口 4 步 → 存宏 → 干跑预检 → 回放 **~200 ms**；改参数回放输入框内容真的变；改坏定位 → 失败在第 1 步 + 「宏可能过期」+ 列表 `stale`。

## 三、审计「人话简报」（`0.2.81`）

起因：**34 列 CSV / JSONL 是"取证级"，不是"阅读级"** —— 老板拿到手只看到哈希和 200 行表。

| 层 | 谁看 | 落点 |
| --- | --- | --- |
| L1 取证 | 审计员 / 脚本 | 原 `.jsonl` / 34 列 CSV / 签名（**一个字都没改**） |
| **L2 简报** | 老板 / 合规 / 甲方 | `audit.brief()` + `render_brief()` → 一页 Markdown；`human_csv()` → 9 列人话 CSV |
| L3 复盘卡 | 案例 / 事故说明 | **还没做**（设计已定稿，见 §十） |

**铁律：这一层不调模型。** `brief()` 是纯函数、`render_brief()` 只套模板 → 同一份记录**永远同一份正文**
（只有"生成时间"那行会变），否则"能当证据"就不成立。

- 骨架固定：一句话结论 → 需要你知道的 3 件事 → 按人 → 按天 → **附录（seq 范围 + 链尾 + 复核命令）**
- 结论按规则拼：`未确认的破坏性` / `已恢复` / `待恢复` / `拦下的敏感读取` / `拒绝` / `失败` / `断链` / `0 条记录`
- 3 件事按严重度挑，**同一条记录的多条说明合并成一行**
- 接口：`GET /audit/brief?format=md|csv[&download=1]`；「另存为」支持 `brief` / `humancsv`
- 面板：信任面板「导出简报…」「导出人话 CSV…」
- 独立 CLI：`tools/cocraft_audit_brief.py <导出.json|.jsonl|-> --format md|csv --out`

**真实输出（节选）**


## 四、`0.2.82`：误导报错 + 一键重启服务

### 4.1 报错不再像"功能坏了"

面板自动重载到新版（带「导出简报」按钮），而 8787 还是旧进程时，后端回
`400 format 只支持 json / csv / md` —— 界面上只剩一行 400。
新增 `backendStaleHint()`（`00-util.js`）：凡是 **400/404/405/"只支持"** 这类失败，都在原话后面补一句
**「面板和后端版本可能不一致：重启一次面板服务 8787 再试」**（审计 5 个导出 + `cu` 动作开关共用）。

### 4.2 真凶：**"重启面板窗口" ≠ "重启服务"**

用户重启过一次面板，仍然报那个 400。查进程才看清：

```
8787 的监听进程 = pid 32404，startedAt 12:56:56（几小时前）   ← 服务没换
面板窗口进程   = pid 32480，19:30:33（刚重启）                ← 只换了窗口
```

**守护进程（watch.py）会一直把 8787 保活** —— 关窗重开只换了窗口进程，后端还是老的，
所以新接口（`/audit/brief`、`/cu/config`）根本不存在。以前只在 AGENTS 里写了"看 pid/startedAt"，
但**没有一个"一键重启服务"的入口**，用户自然会去重启窗口。

补了两件：

| 落点 | 作用 |
| --- | --- |
| `tools/restart_server.py [--port 8787] [--check]` | **只重启面板 HTTP 服务**：按端口找监听进程 → `taskkill` → 等守护拉起（20 s）→ 起不来自己 `Popen(server.py)`；最后打印新 `pid / startedAt / ui`。`--check` 只读状态。读 `/healthz` 用**绕开系统代理**的 opener（踩坑 #45） |
| `scripts/restart-panel-service.bat` | 双击版（纯 ASCII；自动找 `..\python\python.exe` / PATH / `D:\Python312`） |

**实测**：`python tools\restart_server.py` → `[OK] 已重启：pid=10092 启动于 2026-10-27 19:33:49`；
随后 `/audit/brief?format=md` **200（1696 B）**、`?format=csv` **200（16 KB）**、
`/cu/status` 的 `caps` 里出现 `reuse`、`/cu/config` GET **200** —— 新接口全部到位。

## 五、竞品与定位（新增 `docs/竞品与定位.md`）

起因：有人问"Windows 上能恢复删除文件的工具很多吧？Mac 上都有哪些？"
——**对，但那是另一个品类**，而且我们在 SSD 时代比它们强。

| 层 | 代表 | 盲区 |
| --- | --- | --- |
| ① 回收站 | Win/Mac 废纸篓 | **`del` / `Remove-Item` / `rm` 不进回收站**（正是 agent 干的事） |
| ② 系统快照/备份 | VSS、文件历史、Time Machine、APFS 本地快照、OneDrive 版本 | 默认常没开；粒度粗（一天几次/每小时）；**救不了"刚才这 3 秒"**；不知是谁干的 |
| ③ 反删除 | Recuva / DiskGenius / EaseUS / R-Studio / PhotoRec / Windows File Recovery；Mac: Disk Drill / Data Rescue / Stellar | **SSD+TRIM 删除即擦**（Win10/11 默认开，很多机器 24 h 内物理擦除）；**覆盖写无残片**；捞回来无归属 |
| ④ agent 级撤销 | Claude `/rewind`、Cursor、Cline、Zed、Aider、Conductor、Crystal、Superset、Parallel Code、Claude Squad | **只覆盖自家文件编辑**（Claude 官方：Bash 的 `rm/mv/cp` 回不来）；**restore 本身常不可逆**；不落审计；**Mac 上已免费**，Windows 空着 |

**三个硬限制**（为什么恢复软件补不上 agent 的洞）：SSD TRIM / 覆盖写 / 无归属。
**我们的做法绕开全部三条**：破坏性操作**放行前**复制进隔离区 + 每轮内容寻址快照 → 不依赖残片。

**定位一句话**：别人卖"把文件找回来"（赌残片），我们卖"**证明这次动作是谁、凭什么、能不能退，并且退得回来**"（事前留底 + 每步入链）。
**不卖**：壁纸 / 主题 / 音乐 / 多 agent 编排（已经免费）。
